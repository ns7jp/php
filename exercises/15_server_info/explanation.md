# 解説: サーバー情報取得スクリプト

## コードの流れ

`answer.php` は大きく分けて、次のような流れで処理が進みます。

1. **`formatBytes()` 関数を用意する(演習05からの再利用)**
   バイト数を `"1.5 GB"` のような読みやすい文字列に変換する関数です。
   ディスク容量やメモリ使用量は、内部的には常に「バイト数」という
   大きな整数で表現されているため、この変換処理が随所で活躍します。

2. **5つの「情報取得関数」を用意する**
   - `getPhpVersionText()` … `phpversion()` でPHPのバージョンを取得
   - `getOsInfo()` … `PHP_OS` と `php_uname()` でOSの情報を取得
   - `getDiskUsageRows()` … `disk_free_space()` / `disk_total_space()` で
     ディスクの空き容量・総容量・使用率を計算
   - `getLoadAverageText()` … `function_exists()` で確認したうえで
     `sys_getloadavg()` でロードアベレージを取得
   - `getMemoryUsageText()` … `memory_get_usage(true)` でメモリ使用量を取得

   それぞれの関数は「情報を取得して、文字列(または配列)として返す」
   という役割に徹しており、`echo` で直接表示する処理は含んでいません。
   これは、「情報を集める部分」と「画面に表示する部分」を分けておくことで、
   あとから表示方法だけを変更したくなったときに(例えば表形式ではなく
   JSON形式で出力したくなったときなど)、情報取得側のコードに手を
   入れずに済む、という実務でも重視される考え方です。

3. **おまけの `getUptimeSafely()` 関数を用意する**
   `shell_exec()` を使い、`uptime` コマンドの結果を取得する関数です。
   セキュリティ上のリスクを避けるため、外部からの入力を一切受け取らない
   固定のコマンド文字列だけを実行するようにしています。

4. **メイン処理ですべての関数を呼び出し、表形式で表示する**
   各関数の戻り値を `[ラベル, 値]` の組み合わせとして `$rows` という
   配列にまとめ、`mb_strwidth()` でラベルの表示幅を揃えたうえで、
   `foreach` で1行ずつ表示しています。
   最後に、コマンドライン引数に `--with-uptime` が含まれているかどうかを
   `in_array()` でチェックし、含まれている場合だけ `shell_exec()` の
   デモを実行します。

## 重要なポイント(使用した関数・構文の解説)

- **`phpversion()`**
  引数なしで呼び出すと、今このスクリプトを実行しているPHP自体の
  バージョンを文字列(例: `"8.4.19"`)で返します。サーバーのトラブル
  シューティングでは、まず「PHPのバージョンは何か」を確認することが
  多く、非常によく使われる関数です。

- **`PHP_OS`(定数)と `php_uname()`(関数)**
  `PHP_OS` はPHPが**あらかじめ用意している定数**で、OSの種類
  (`"Linux"`, `"WINNT"`, `"Darwin"` など)が文字列として入っています。
  定数なので `()` を付けずに、そのまま `PHP_OS` と書いて使います。
  一方 `php_uname()` は関数で、OS名だけでなくホスト名やカーネルの
  バージョンなど、より詳しい情報をまとめた1つの文字列を返します。
  どちらも「実行環境の情報を知りたいとき」に使う点は共通していますが、
  「定数」と「関数」という文法上の違いがある点に注意してください。

- **`disk_free_space($path)` / `disk_total_space($path)`**
  指定したパス(`$path`)が存在するディスク(パーティション)の
  空き容量・総容量を、それぞれバイト単位の `float` で返す関数です。
  `"."` を渡すと、「スクリプトを実行したときのカレントディレクトリ」が
  存在するディスクの容量を調べることになります。
  環境によっては情報を取得できず `false` が返ってくることがあるため、
  `if ($free === false || ...)` のように、必ず `false` かどうかを
  チェックしてから使うのが安全です。

- **`function_exists("関数名")`**
  指定した名前の関数が、今の実行環境で定義されている(呼び出せる)
  かどうかを `true` / `false` で返す関数です。
  `sys_getloadavg()` のように、環境(特にOSの種類)によって
  使えるかどうかが変わる関数を呼び出す前には、このように
  `function_exists()` で事前にチェックしておくことで、
  「存在しない関数を呼び出してしまい、スクリプトが致命的エラーで
  止まる」という事態を防ぐことができます。

  ```php
  if (!function_exists('sys_getloadavg')) {
      // 使えない環境向けの代わりの処理
  } else {
      $load = sys_getloadavg();
      // 使える環境向けの処理
  }
  ```

- **`sys_getloadavg()`**
  直近の「ロードアベレージ(CPUの処理待ちがどれくらい発生していたか
  を表す負荷の指標)」を、`[1分平均, 5分平均, 15分平均]` という
  3要素の配列(`float`)で返す関数です。Linux/UnixサーバーではWebサーバーや
  データベースサーバーの負荷を確認する基本的な指標として使われますが、
  **Windows環境ではこの関数自体が定義されておらず使えません**。

- **`memory_get_usage(bool $real_usage = false)`**
  今実行中のPHPスクリプトが使用しているメモリ量をバイト単位で返す
  関数です。引数に `true` を渡すと、OSから実際に確保している
  メモリ量全体(real usage)を取得できます。長時間動くバッチ処理や
  デーモンスクリプトでは、この値を定期的に確認することで
  「メモリリーク」の兆候に早く気づくことができます。

- **`mb_strwidth($string)`**
  文字列の「表示幅」を計算する関数です(mbstring拡張が提供します)。
  半角文字(英数字など)を1、全角文字(日本語など)を2として数えるため、
  日本語と英数字が混在する文字列でも、表示上の幅を正確に揃えることが
  できます。通常の `str_pad()` は「バイト数」で長さを判断してしまうため、
  日本語を含む文字列の桁揃えには不向きです。今回の表形式の表示では、
  この違いを利用してラベルの位置をきれいに揃えています。

- **`shell_exec($command)`**
  OSのシェルコマンドをそのまま実行し、その出力結果を文字列として
  受け取れる関数です。非常に強力な分、使い方を誤ると重大な
  セキュリティ上の問題(コマンドインジェクション)を引き起こします。
  詳しくは次の「初心者がつまずきやすいポイント」で解説します。

## 初心者がつまずきやすいポイント

- **`shell_exec()` に外部からの入力をそのまま渡してしまう**
  これが今回の演習でもっとも強調したい注意点です。
  たとえば、次のようなコードは**絶対に書いてはいけません**。

  ```php
  $host = $_GET['host'];               // 外部からの入力をそのまま受け取る
  $result = shell_exec("ping -c 1 " . $host); // 危険!
  ```

  もし `$host` に `"example.com; rm -rf /"` のような文字列を渡されると、
  本来意図した `ping` コマンドだけでなく、セミコロン(`;`)の後ろに
  続く別のコマンドまで実行されてしまう可能性があります。
  これを「コマンドインジェクション」と呼び、実際のWebサービスでも
  繰り返し報告されている代表的な脆弱性の1つです。
  対策の基本は「外部からの入力をコマンド文字列に混ぜない」ことで、
  今回の演習でも `getUptimeSafely()` は固定の文字列 `'uptime'` のみを
  渡すことで、この危険を避けています。どうしても外部の値を
  コマンドに組み込む必要がある場合は、`escapeshellarg()` などによる
  厳重なエスケープ処理が必須になりますが、初心者のうちは
  「そもそも使わない」判断が最も安全です。

- **`PHP_OS` に `()` を付けてしまう**
  `PHP_OS` は定数であり、関数ではありません。`PHP_OS()` のように
  `()` を付けて呼び出そうとすると、`Fatal error` になってしまいます。
  「定数は値がそのまま入っている箱」「関数は呼び出して初めて値が
  返ってくる仕組み」という違いを意識しましょう。

- **`disk_free_space()` などが `false` を返す可能性を忘れる**
  「必ずバイト数(数値)が返ってくるはず」と思い込んでいると、
  `false` が返ってきた場合に、その後の計算(割り算など)で
  警告やエラーが発生することがあります。外部の情報(ディスク、
  OS、ネットワークなど)を取得する関数は、常に「取得できない
  可能性」を考えて `false` や `null` のチェックを書く習慣を
  つけましょう。

- **`function_exists()` のチェックを書き忘れて `sys_getloadavg()` を
  いきなり呼び出してしまう**
  開発時に使っている環境(多くはLinuxやmacOS)ではこの関数が
  使えるため気づきにくいのですが、Windows環境や一部の共有サーバー
  環境ではこの関数が存在せず、事前チェックをしていないと
  `Fatal error: Uncaught Error: Call to undefined function
  sys_getloadavg()` でスクリプトが止まってしまいます。

- **`disk_free_space()` の戻り値(float)を、そのまま `formatBytes(int $bytes)` に渡してしまう**
  `disk_free_space()` や `disk_total_space()` は `float` 型の値を
  返しますが、演習05の `formatBytes()` は引数に `int` 型を要求する
  型宣言になっています。このファイルでは `declare(strict_types=1);`
  を使っていない(PHPの初期設定である「弱い型付け」のままの)ため、
  float をそのまま渡してもエラーにはならず、PHPが自動的に `int` に
  変換してくれます。ただし、小数点以下の値が失われるような変換の
  場合は `Deprecated: Implicit conversion from float ... to int loses
  precision` という非推奨の警告が出ることがあります。
  意図がわかりやすいコードにするため、また将来 `declare(strict_types=1);`
  を付けることになった場合にも困らないように、
  `formatBytes((int) $free)` のように明示的に `(int)` でキャスト
  (型変換)しておくのが良い習慣です。

## よくあるエラーと対処法

- **`Fatal error: Uncaught Error: Call to undefined function sys_getloadavg()`**
  `sys_getloadavg()` が使えない環境(主にWindows)で、
  `function_exists()` によるチェックをせずに呼び出してしまった場合に
  発生します。呼び出す前に必ず `function_exists('sys_getloadavg')` で
  確認し、`false` の場合は代わりのメッセージを表示するようにしましょう。

- **`Fatal error: Uncaught Error: Call to undefined function PHP_OS()`**
  `PHP_OS` は定数であり、関数ではないため `PHP_OS()` のように `()` を
  付けて呼び出すことはできません(「`PHP_OS` という名前の関数」を
  呼び出そうとしたことになり、そのような関数は存在しないためこの
  エラーになります)。`PHP_OS` とそのまま書くか、関数として使いたい
  場合は `php_uname('s')` のように `php_uname()` 関数を使いましょう。

- **`Fatal error: Uncaught DivisionByZeroError: Division by zero`**
  `disk_total_space()` が `0` や `false` を返した状態のまま、
  使用率を計算する `$used / $total` のような割り算を行うと発生します。
  PHP 7以前ではゼロ除算は単なる`Warning`(警告)で、計算結果は
  `INF`(無限大)などになって処理はそのまま続いていましたが、
  PHP 8以降は`/`演算子でのゼロ除算は`DivisionByZeroError`という
  **例外(Fatal error)としてスクリプトが停止する**ように変更されました。
  そのため、このスクリプトを動かしているPHPのバージョンに関わらず、
  計算の前に `$total <= 0` かどうかを必ずチェックし、その場合は
  計算を行わずに「取得できません」というメッセージを返すようにしましょう。

- **`Deprecated: Implicit conversion from float ... to int loses precision`**
  `disk_free_space()` などが返す `float` 型の値を、`int` 型を要求する
  `formatBytes()` に(明示的な `(int)` キャストを付けずに)そのまま
  渡したときに、小数点以下の情報が失われる場合に表示される警告です。
  このファイルは `declare(strict_types=1);` を使っていないため、
  型が合わなくても `Fatal error`(致命的エラー)にはならず処理は
  続行されますが、意図しない警告が出ないようにするためにも、
  `formatBytes((int) $free)` のように、明示的に `(int)` でキャストしてから
  渡す習慣をつけましょう。
  (なお、もしファイルの先頭に `declare(strict_types=1);` を付けていた
  場合は、型が合わないと `Fatal error: Uncaught TypeError:
  formatBytes(): Argument #1 ($bytes) must be of type int, float given`
  という致命的エラーになります。)

- **`shell_exec()` を使った処理が「実行できません」という結果ばかり返す**
  `shell_exec()` 自体がサーバーの設定(`disable_functions` など)で
  無効化されている環境では、正常な実行結果ではなく `null` が
  返ってきます。これは異常なことではなく、むしろセキュリティ上の
  理由から意図的に無効化されている、比較的よくある本番サーバーの
  設定です。`function_exists('shell_exec')` でのチェックと、
  `null` チェックの両方が必要になる理由はここにあります。

## まとめ

- `phpversion()`, `PHP_OS`, `php_uname()` を使うと、今このスクリプトが
  動いている実行環境(PHPのバージョンやOS)の情報を取得できます。
- `disk_free_space()` と `disk_total_space()` を組み合わせることで、
  ディスクの空き容量・総容量・使用率を計算できます。ただし戻り値が
  `false` になる可能性を考慮した、安全なチェックが欠かせません。
- `sys_getloadavg()` のように「環境によって使えるかどうかが変わる関数」を
  呼び出す前には、`function_exists()` で存在確認をしてから使うのが
  安全な書き方です。この習慣は、開発環境と本番環境の違いに
  振り回されないための、実務でも非常に重要な考え方です。
- `memory_get_usage(true)` を使うと、PHPスクリプトが実際に使用している
  メモリ量を確認できます。長時間動く処理のメモリリーク対策として
  役立ちます。
- `shell_exec()` は非常に強力な関数ですが、外部からの入力を
  そのまま渡すと「コマンドインジェクション」という重大な脆弱性に
  つながります。使う場合は、外部からの入力を一切含まない固定の
  コマンドに限定するなど、厳重な注意が必要です。
- 今回作ったツールのように「サーバーの状態をPHPで可視化する」という
  発想は、実際の監視ツールやサーバー管理画面の基本的な仕組みそのもので
  あり、サーバー構築エンジニアを目指すうえで象徴的な題材の1つです。
