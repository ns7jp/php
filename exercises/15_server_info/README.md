# 演習15: サーバー情報取得スクリプト

## この演習で学ぶこと

- `sys_getloadavg()`, `disk_free_space()`, `disk_total_space()` など、
  サーバーの状態を調べる組み込み関数を使えるようになる
- `phpversion()`, `PHP_OS`, `php_uname()` で、今スクリプトが動いている
  実行環境の情報を取得できるようになる
- `function_exists()` を使い、「その関数が今の環境で使えるかどうか」を
  安全に事前チェックしてから呼び出す書き方を身につける
- `shell_exec()` を使うときのセキュリティ上の注意点(コマンドインジェクション)を
  正しく理解する

## 前提知識

- 演習14(例外処理とエラーログ)の内容を理解していること
  - `try` / `catch` を使った例外処理の基本
  - 「想定外の事態が起きたときに、どう安全に対処するか」という考え方
- 演習05(関数の作成)で作った `formatBytes()` 関数の考え方
  - バイト数を読みやすい単位(KB, MB, GB など)に変換する処理
- 演習01〜04で学んだ変数、条件分岐、配列、関数呼び出しの基本

## 演習内容(要件)

今このPHPスクリプトが動いている「サーバー(実行環境)」について、
次の5つの情報を取得し、見やすい一覧(表形式のテキスト)としてコンソールに
出力するCLI(コマンドライン)ツールを作りましょう。

1. **PHPのバージョン**
   `phpversion()` を使って取得します。

2. **OS名**
   `PHP_OS`(定数)または `php_uname()`(関数)を使って取得します。
   このツールでは両方を表示し、違いを比較できるようにします。

3. **ディスクの空き容量・総容量・使用率**
   `disk_free_space(".")` と `disk_total_space(".")` を使い、
   カレントディレクトリが存在するディスクの空き容量・総容量をバイト単位で取得します。
   そこから「使用中の容量」と「使用率(%)」を計算し、
   演習05の `formatBytes()` のような関数を使って読みやすく表示します。

4. **ロードアベレージ(直近の負荷状況)**
   `sys_getloadavg()` を使って取得します。
   ただし、この関数は**Windows環境では使えない**ため、
   `function_exists("sys_getloadavg")` で「今の環境で使える関数かどうか」を
   事前に確認し、使えない環境では
   「この環境では取得できません」のようなメッセージを表示するようにします。

5. **メモリ使用量**
   `memory_get_usage(true)` を使い、PHPが実際にOSから確保している
   メモリ量を取得し、これも読みやすい単位に変換して表示します。

さらに、**おまけ・オプションの機能**として、`shell_exec()` を使った例を
1つだけ用意します。

- `shell_exec()` は非常に強力な関数で、外部からの入力(ユーザー入力など)を
  検証せずにそのまま渡してしまうと、「コマンドインジェクション」という
  重大なセキュリティ上の脆弱性につながります。
- そのため今回は、**外部からの入力を一切受け取らない、`uptime` という
  引数なしの固定コマンドだけ**を安全な例として実行します。
  この注意点はコード中のコメントと、`explanation.md` にも詳しく記載します。

## 実行方法

ターミナル(コマンドライン)で、この演習のディレクトリに移動してから
以下のコマンドを実行してください。

```bash
# 未完成のひな形を実行してみる(エラーにはならず、TODO部分だけ「まだ実装されていません」等と表示されます)
php practice.php

# 模範解答を実行する
php answer.php
```

`--with-uptime` というオプションを付けると、`shell_exec()` を使った
おまけのデモも確認できます。

```bash
php answer.php --with-uptime
```

`practice.php` の中の `// TODO:` と書かれた部分を自分で実装してから、
もう一度 `php practice.php` を実行し、`answer.php` と同じような結果が出るか
確認してみましょう。

構文だけを素早く確認したいときは、次のコマンドも便利です。

```bash
php -l practice.php
```

## ヒント

- `sys_getloadavg()` はWindows環境では使えないため、`function_exists()` で
  事前にチェックするのが安全です。存在しない関数をいきなり呼び出すと
  `Fatal error` でスクリプトが止まってしまいます。
- `disk_free_space()` や `disk_total_space()` はバイト単位(かなり大きな数値)で
  返ってくるので、演習05の `formatBytes()` のような関数で読みやすく変換すると
  親切です。
- `disk_free_space()` や `disk_total_space()` は、環境によっては情報を
  取得できず `false` を返すことがあります。使う前に `false` かどうかを
  必ずチェックしましょう(チェックしないと、ゼロ除算などの思わぬエラーの
  原因になります)。
- `shell_exec()` に外部からの入力(ユーザー入力など)をそのまま渡すと
  「コマンドインジェクション」という重大な脆弱性になるため、
  **原則として使わない**、**使う場合は渡す内容を厳しく制限する**ことが重要です。
  今回のように「引数を持たない固定の文字列だけを渡す」のは、比較的安全な
  使い方の一例です。
- 日本語(全角文字)を含む文字列の表示幅を揃えたいときは、`str_pad()` では
  ずれてしまうことがあります。`mb_strwidth()` を使うと、全角・半角が
  混在していてもきれいに揃えられます(`answer.php` の表示部分で使っています)。

## サーバーエンジニアとの関連

この演習は、**サーバー構築エンジニア職の実務に最も直結する内容**です。
「PHPを使ってサーバーの状態を可視化する」というのは、ポートフォリオとしても
象徴的な一本になります。

- 実務のサーバー運用では、「今このサーバーは正常に動いているか」
  「ディスク容量は足りているか」「負荷は高くないか」を、日々確認する
  必要があります。今回作ったようなスクリプトは、その基本形そのものです。
- 実際の監視ツール(Zabbix、Datadog、Mackerel など)や、多くの
  サーバー管理画面(レンタルサーバーのコントロールパネルなど)も、
  裏側では今回学んだような「OSやディスク、メモリの情報をプログラムから
  取得する」処理を組み合わせて、グラフや一覧画面として表示しています。
- 「ディスクの空き容量が少なくなったら管理者にメールで通知する」
  「ロードアベレージが一定値を超えたらアラートを出す」といった
  自動監視の仕組みも、根本的には今回作った「情報を取得する処理」に
  「しきい値と比較する処理」を組み合わせることで実現できます。
- `function_exists()` によるチェックは、「開発環境と本番環境でPHPの設定や
  OSが違う」といった実務でよくある状況に対応するための、
  **地味だが非常に重要な安全策**です。動くはずの関数がある日突然
  使えなくなっていた、というトラブルを未然に防いでくれます。
- `shell_exec()` のセキュリティ上の注意点を正しく理解しておくことは、
  「サーバーを守る側」であるサーバー構築エンジニアにとって特に重要な
  知識です。コマンドインジェクションは、実際のWebサービスでも
  繰り返し報告されている代表的な脆弱性の1つです。
