# 解説: セッション・Cookie管理

## コードの流れ

`answer.php` は大きく分けて、次の流れで処理を行っています。

1. **`session_start()` と `setcookie()` を、ファイルの一番最初で呼び出す**
   どちらも「他の出力より前に呼ばなければならない」という制約が
   あるため、`echo` などの出力処理よりも前にまとめて呼び出しています。
   `session_start()` によって `$_SESSION` が使えるようになり、
   `setcookie()` によって「最終アクセス日時」を記録するCookieを
   1つ設定しています。

2. **`checkLoginStatus()` 関数の定義**
   `$_SESSION['logged_in']` を確認し、ログイン中かどうかによって
   「ログイン中のユーザー: admin」または「ログインしていません」と
   いう文字列を返す関数です。ログイン直後と、ログアウト後の
   2つのタイミングで、この同じ関数を呼び出して使い回しています。

3. **`$_POST` のシミュレーションと、ログイン処理**
   本来ブラウザから送られてくる `$_POST['id']` / `$_POST['password']`
   を、CLIで試せるようにあらかじめ配列として用意しています。
   固定の正しいID・パスワードと `===` で比較し、一致すれば
   `$_SESSION['logged_in'] = true;` と `$_SESSION['user'] = 'admin';`
   を実行してログイン状態を保存しています。

4. **Cookieの確認**
   手順1で設定した `last_access` Cookieについて、`$_COOKIE` から
   値を読み取れるかどうかを確認しています。CLIで実行している
   ため、この時点ではまだ `$_COOKIE['last_access']` に値は
   入っていません(理由は後述します)。

5. **ログイン確認処理**
   `checkLoginStatus()` を呼び出し、ログイン処理で保存した
   `$_SESSION` の内容が正しく読み取れることを確認しています。

6. **ログアウト処理と、その後の再確認**
   `session_destroy()` でサーバー側のセッションデータを破棄し、
   `$_SESSION = [];` でスクリプト内の `$_SESSION` も空にしたうえで、
   もう一度 `checkLoginStatus()` を呼び出し、今度は
   「ログインしていません」と表示されることを確認しています。

## 重要なポイント(使用した関数・構文の解説)

- **`session_start()`**
  セッションを開始(または、既に始まっている場合はそのデータを
  復元)する関数です。この関数を呼ぶことで、以降 `$_SESSION` という
  スーパーグローバル変数(どの関数の中からでもアクセスできる、
  特別な配列)が使えるようになります。
  内部的には、
  1. まだセッションが始まっていなければ、ランダムな文字列である
     「セッションID」を新しく発行する
  2. サーバー側の保存領域(多くの場合、サーバー内のファイル)から、
     そのセッションIDに対応するデータを読み込んで `$_SESSION` に
     復元する
  という2つのことを行っています。ブラウザ経由でアクセスする場合、
  このセッションIDは自動的にCookie(`PHPSESSID` という名前が
  よく使われます)としてブラウザに保存され、次にアクセスしてきた
  ときにブラウザがそのCookieを送り返すことで、「同じ利用者からの
  アクセスである」とサーバーが認識できるようになります。

- **`$_SESSION`**
  `session_start()` を呼び出した後に使える、連想配列形式の
  スーパーグローバル変数です。ここに保存した値は、
  (ブラウザ経由でアクセスしている場合)同じセッションIDを持つ
  次のリクエストでも引き継がれます。ログイン状態やカート内の
  商品など、「そのユーザーに関する一時的な情報」を保存するのに
  よく使われます。

- **`setcookie($name, $value, $expire)`**
  ブラウザに対して「この名前と値の組み合わせを保存しておいて、
  次回以降のアクセス時に送り返してください」と指示するための
  関数です。第3引数にはCookieの有効期限をUNIXタイムスタンプ
  (1970年1月1日からの経過秒数)で指定します。
  `time() + 60 * 60 * 24 * 30` のように書くと、「今から30日後」
  という有効期限を表せます。

- **`session_destroy()`**
  サーバー側に保存されているセッションデータ(セッションファイル
  など)を破棄する関数です。これにより、以後同じセッションIDで
  アクセスしてきても、それまで保存されていたログイン情報などは
  読み込めなくなります。ただし、実行中のスクリプトの中に既に
  読み込まれている `$_SESSION` 配列の中身までは自動的に空に
  ならない点に注意が必要です。「見た目上もログアウトした状態」を
  再現するために、この演習では `session_destroy()` の直後に
  `$_SESSION = [];` を実行し、配列そのものも空にしています。

- **`isset($_SESSION['logged_in'])`**
  変数(や配列の要素)が「存在していて、かつ `null` ではないか」を
  確認する関数です。まだログインしていない状態や、ログアウト後で
  `$_SESSION` が空の状態で、いきなり `$_SESSION['logged_in']` に
  アクセスすると警告が出てしまいますが、`isset()` で先に確認して
  おくことで、警告を出さずに安全にチェックできます。

- **`htmlspecialchars($_SESSION['user'], ENT_QUOTES, 'UTF-8')`**
  演習10でも扱った、HTMLタグとして解釈される可能性のある文字を
  無害な文字列に変換する関数です。`$_SESSION` の中身は、元をたどれば
  ユーザー自身が入力した値である場合が多いため、画面(実際には
  Webページ)に表示する前には、今回のようにこの関数を通す習慣を
  付けておきましょう。

## 初心者がつまずきやすいポイント

- **`session_start()` を `echo` の後に書いてしまう**
  `session_start()` は内部的に「セッションIDをCookieとして保存して
  ください」というレスポンスヘッダーを送ろうとします。しかし、
  一度でも `echo` などで画面に出力すると、PHPは「ヘッダー部分の
  送信はもう終わった」ものとして扱ってしまうため、それより後に
  `session_start()` を呼び出すと警告が出てしまいます。
  `session_start()` と `setcookie()` は、必ずファイルの一番最初、
  他のどんな出力よりも前に呼び出すようにしましょう。

- **`session_destroy()` を呼べば `$_SESSION` も空になると思い込む**
  `session_destroy()` が破棄するのは、あくまで「サーバー側に
  保存されているデータ」です。既に `$_SESSION` に読み込まれている
  値そのものは、スクリプトが終了するまでメモリ上に残り続けます。
  ログアウト後に改めて `$_SESSION` の中身を確認したい場合は、
  `session_destroy()` とあわせて `$_SESSION = [];` を実行する
  ようにしましょう。

- **CLIで実行しても、ブラウザと同じ感覚で「セッションが保持される」と
  思ってしまう**
  ブラウザでWebアプリケーションにアクセスする場合、1回
  `session_start()` が実行されると、以後はブラウザが自動的に
  セッションIDのCookieを保存し、ページを移動するたびに(=次の
  HTTPリクエストのたびに)そのCookieを送り返してくれます。
  そのおかげで、「ログインしたら、別のページに移動してもログイン
  状態が保たれている」という動きが実現できています。
  一方、CLIで `php answer.php` のようにスクリプトを実行する場合、
  そもそも「ブラウザ」も「複数回のHTTPリクエスト」も存在しません。
  スクリプトを実行するたびに、PHPは(特別なことをしない限り)
  毎回まったく新しいセッションIDを発行します。
  そのため、この演習ではあえて「ログイン→確認→ログアウト」という
  一連の流れを **1回の実行の中で** シミュレートすることで、
  `$_SESSION` の値が正しく引き継がれる様子を再現しています。
  複数回 `php answer.php` を実行しても、前回ログインした情報が
  残っていて自動的にログイン済み扱いになる、ということは
  起こりません(実際のブラウザでの体験とは異なる点なので、
  覚えておきましょう)。

- **`setcookie()` を呼んだ直後に、同じスクリプトの中で
  `$_COOKIE` を読んでも値が入っていない**
  `setcookie()` は「次のアクセス時に送り返してください」という
  指示をブラウザに送るための関数であり、呼び出した瞬間に
  現在の `$_COOKIE` の中身を書き換えるものではありません。
  ブラウザで動いている場合は、次のページ読み込みから
  `$_COOKIE['last_access']` に値が入るようになりますが、
  CLIでは「次のページ読み込み」自体が存在しないため、
  この演習のように `setcookie()` の直後に `$_COOKIE` を確認すると、
  まだ値が入っていない状態を観測することになります。これは
  バグではなく、CLIとブラウザでの動作の違いによる、正常な結果です。

## よくあるエラーと対処法

- **`Warning: session_start(): Session cannot be started after headers have already been sent`**
  `session_start()` を呼び出す前に、既に `echo` などで何かを
  出力してしまっている場合に発生します。`session_start()` は
  ファイルの一番最初、他のどの出力よりも前に呼び出すようにしましょう。
  `<?php` の前に空白や改行が入ってしまっている場合にも、
  「見えない出力」として扱われて同じ警告が出ることがあるので
  注意してください。

- **`Warning: Cannot modify header information - headers already sent by ...`**
  `setcookie()` を、既に何か出力した後に呼び出してしまった場合に
  発生します。上と同様に、`setcookie()` もファイルの一番最初に
  移動しましょう。

- **`Warning: Undefined array key "logged_in"`**
  `isset()` によるチェックをせずに、いきなり
  `if ($_SESSION['logged_in'] === true)` のように書いてしまうと、
  まだログインしていない状態やログアウト後にこの警告が出ます。
  `isset($_SESSION['logged_in']) && $_SESSION['logged_in'] === true`
  のように、必ず `isset()` と組み合わせて確認しましょう。

- **ログアウトしたはずなのに、`checkLoginStatus()` が
  「ログイン中」と表示され続ける**
  `session_destroy()` だけを呼び、`$_SESSION = [];` を
  実行し忘れているとこの状態になります。`session_destroy()` は
  サーバー側の保存データを消すだけで、スクリプト内の `$_SESSION`
  配列自体は空にしてくれないことを思い出しましょう。

- **`session_start(): open(...): Failed to open stream` のような
  ファイル関連の警告**
  セッションデータを保存するディレクトリへの書き込み権限がない
  場合などに発生することがあります。実行環境(サーバーの設定)に
  よる問題であることが多いため、まずは自分のPHP環境の
  `session.save_path` の設定や、そのディレクトリの権限を
  確認してみましょう。

## まとめ

この演習では、Webアプリケーションの「ログイン状態を保つ仕組み」の
基礎となる、セッションとCookieの扱い方を学びました。

- `session_start()` を呼び出すと、`$_SESSION` という
  スーパーグローバル変数が使えるようになり、サーバー側に
  ユーザーごとの情報を保存・復元できるようになります。
- `$_SESSION` に保存した値は、ブラウザ経由でアクセスしている場合、
  同じセッションIDを持つ複数のリクエストにまたがって引き継がれます。
- `setcookie()` を使うと、ブラウザ側に小さな情報(この演習では
  「最終アクセス日時」)を保存できます。実際のWebアプリケーションでは、
  セッションIDそのものもCookieとしてブラウザに保存されています。
- `session_destroy()` はサーバー側のセッションデータを破棄する
  関数ですが、スクリプト内の `$_SESSION` 配列自体を空にするには
  別途 `$_SESSION = [];` を組み合わせる必要があります。
- セッションは「サーバー側にデータを保存する仕組み」、Cookieは
  「ブラウザ側に小さな情報(多くの場合はセッションIDだけ)を
  保存する仕組み」という役割分担を理解しておくと、Webアプリケーションが
  どのようにして「ログインしたユーザーを覚えている」のかが
  イメージしやすくなります。
- CLIでの実行はWebブラウザ経由でのアクセスとは異なり、「複数回の
  リクエストにまたがるセッションの継続」を体験することはできません。
  この演習のように、1回のスクリプト実行の中で
  「ログイン→確認→ログアウト」の流れをシミュレートすることで、
  仕組みそのものを理解することを目的としています。
  管理画面のログイン機能やユーザーの状態維持は、実際に
  Webサーバーを運用するうえで避けて通れない知識なので、
  ここで学んだ関数の役割をしっかり押さえておきましょう。
