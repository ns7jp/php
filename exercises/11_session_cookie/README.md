# 演習11: セッション・Cookie管理

## この演習で学ぶこと

- `session_start()` を呼び出して、`$_SESSION` というスーパーグローバル変数を
  使えるようにする方法を理解する
- `$_SESSION` に値を保存し、あとから読み取ることで
  「ログイン状態」のようなユーザーごとの情報を維持する仕組みを理解する
- `setcookie()` を使って、ブラウザ側に小さな情報(Cookie)を
  保存する方法を理解する
- `session_destroy()` を使って、ログアウト処理(セッション情報の破棄)を
  実装できるようになる
- セッション(サーバー側にデータを保存する仕組み)と
  Cookie(ブラウザ側にIDなどの小さな情報を保存する仕組み)の
  役割の違いを理解する

## 前提知識

- 演習10(フォーム処理とバリデーション)の内容を理解していること
  - `$_POST` をCLIでシミュレートするやり方
  - `htmlspecialchars()` を使ったXSS対策の考え方
- 演習01〜05で学んだ変数、条件分岐、配列、関数の基本
  - 特にこの演習では `checkLoginStatus()` という関数を1つ定義します

## 演習内容(要件)

サーバー管理ツールの「管理画面ログイン」を想定した、簡易的な
ログイン処理を作ります。本来はHTMLの `<form>` から送信された値を
使いますが、この演習でも演習10と同じく、**CLI(コマンドライン)だけで
動作確認できるように** `$_POST` にあらかじめ次のような配列を
直接代入してシミュレートします。

```php
// 本来はログインフォームから送信される値ですが、
// この演習ではCLIで試せるように直接配列を代入しています。
$_POST = [
    'id'       => 'admin',
    'password' => 'password123',
];
```

あらかじめ決めておいた固定のID・パスワード(`admin` / `password123`)と
`$_POST` の値を比較し、一致すればログイン成功として扱います。
1つのファイルの中で、次の流れを順番にシミュレートしてください。

### 1. ログイン処理

- `$_POST['id']` と `$_POST['password']` が、固定の正しい値
  (`admin` / `password123`)と一致するか `===` で比較する。
- 一致した場合は、`session_start()` した状態で(**必ず他の出力より前に
  呼び出すこと**)、次のように `$_SESSION` へ状態を保存する。

  ```php
  $_SESSION['logged_in'] = true;
  $_SESSION['user'] = 'admin';
  ```

- 「ログインに成功しました」と表示する。一致しなかった場合は
  「IDまたはパスワードが正しくありません」のように表示する。

### 2. Cookie(最終アクセス日時)の設定

- `setcookie()` を使って、`last_access` という名前で
  「今日の日時」を値としたCookieを設定する(こちらも
  他の出力より前に呼び出すこと)。
- CLIではこのCookieが実際にブラウザへ届くわけではないため、
  同じスクリプトの中で `$_COOKIE['last_access']` を読み取っても
  まだ値が入っていないことを確認してみる(詳しくは`explanation.md`)。

### 3. ログイン確認処理

- ログイン処理とは別の処理として、`$_SESSION` の内容を読み取り、
  ログイン中であれば「ログイン中のユーザー: admin」のように表示する
  処理を作る(この演習では `checkLoginStatus()` という関数として
  実装します)。
- ログインしていない場合は「ログインしていません」と表示する。

### 4. ログアウト処理

- `session_destroy()` を呼び出して、サーバー側のセッションデータを
  破棄する。
- あわせて `$_SESSION = [];` として、スクリプト内で使っている
  `$_SESSION` 配列の中身も空にする(理由は「ヒント」と
  `explanation.md` で説明します)。
- ログアウト後にもう一度ログイン確認処理を呼び出し、
  「ログインしていません」と表示されることを確認する。

## 実行方法

ターミナル(コマンドライン)で、この演習のディレクトリに移動してから
以下のコマンドを実行してください。

```bash
cd exercises/11_session_cookie

# 未完成のひな形を実行してみる(エラーにはならず、TODO部分だけ「まだ実装されていません」と表示されます)
php practice.php

# 模範解答を実行する
php answer.php
```

`practice.php` の中の `// TODO:` と書かれた部分を自分で実装してから、
もう一度 `php practice.php` を実行し、`answer.php` と同じような結果が
出るか確認してみましょう。

構文だけを素早く確認したいときは、次のコマンドも便利です。

```bash
php -l practice.php
```

試しに `$_POST['password']` の値を間違ったもの(例: `"wrongpass"`)に
書き換えて実行し、ログインに失敗した場合の表示がどう変わるかも
確認してみましょう。

## ヒント

- `session_start()` は、他の出力(`echo` など)より前に呼び出す
  必要があります。PHPは一度でも画面に文字を出力すると
  「レスポンスヘッダーの送信」を済ませたものとして扱うため、
  それより後に `session_start()` や `setcookie()` を呼び出すと
  「Cannot modify header information - headers already sent」という
  警告が出てしまいます。この2つの関数は必ずファイルの一番最初に
  まとめて呼び出しましょう。
- CLI(コマンドライン)で実行する場合、Webブラウザのようにセッションが
  ブラウザに紐づかないため、動作確認の見え方が少し異なります。
  たとえば `php answer.php` を実行するたびに、毎回まったく新しい
  セッションが発行されます(ブラウザでアクセスしたときのように、
  「前回訪れたときのログイン状態」が引き継がれることはありません)。
  この違いについては `explanation.md` で詳しく解説しています。
- セッションはサーバー側にデータを保存し、Cookieはブラウザ側に
  IDなどの小さな情報を保存する、という役割の違いを理解しましょう。
  実際のWebアプリケーションでは、Cookieには「どのセッションデータを
  読みに行けばよいか」を示すセッションID(`PHPSESSID` など)だけが
  保存され、ログイン中のユーザー名のような具体的な情報自体は
  サーバー側の `$_SESSION` に保存されます。
- `session_destroy()` はサーバー側のセッションデータを破棄しますが、
  呼び出した後も、実行中のスクリプトの中にある `$_SESSION` 配列
  そのものは自動的には空になりません。ログアウト後の状態を
  正しく再現するには、`$_SESSION = [];` を組み合わせて使いましょう。
- `isset($_SESSION['logged_in'])` のように `isset()` を使うことで、
  まだログインしていない(キーが存在しない)状態でも警告を出さずに
  安全にチェックできます。

## サーバーエンジニアとの関連

管理画面のログイン機能や、ユーザーの状態を維持する仕組みは、
Webサーバーを運用するうえで必須の知識です。

- サーバー監視ツールやクラウドの管理コンソールなど、多くの管理画面には
  「ログインしたユーザーだけが操作できる」という仕組みが必須です。
  この演習で学んだ「`session_start()` でセッションを始め、
  `$_SESSION` にログイン状態を保存し、以降のページでその情報を
  読み取って確認する」という流れは、そうした管理画面の認証機能の
  基礎そのものです。
- ログイン状態を安全に保つには、`session_destroy()` による
  ログアウト処理も欠かせません。ログアウト機能が正しく実装されて
  いないと、共有パソコンなどで管理画面にログインしたまま
  ブラウザを閉じてしまい、別の人が同じセッションで操作できてしまう
  といったセキュリティ上の問題につながります。
- Cookieの役割を正しく理解しておくことも重要です。実務では、
  セッションIDを保存するCookieに `Secure`(HTTPS通信でのみ送信)や
  `HttpOnly`(JavaScriptからのアクセスを禁止)といった属性を
  付けることで、Cookieの盗み見や不正利用を防ぐ設定を行います。
  この演習はその手前の「そもそもセッションとCookieはどう役割分担
  しているのか」という基礎を体験するためのものです。

## 発展課題

余裕がある人は、以下にも挑戦してみましょう。

- ログイン試行の回数を数える仕組みを追加してみましょう。
  `$_SESSION['login_attempts']` のような値を用意し、ログインに
  失敗するたびに1ずつ増やして、「3回失敗したら
  『しばらく時間をおいてから再度お試しください』と表示して
  それ以上のログインを受け付けない」という簡単なロック機能を
  作ってみましょう(ログインに成功した場合は、この回数を
  `0` にリセットするのを忘れないようにしましょう)。
