# 解説: 演算子と条件分岐

## コードの流れ

`answer.php` は大きく4つのパートに分かれています。

1. **ディスク空き容量の判定**
   `$diskFreePercent` という数値の変数を用意し、`if` / `elseif` / `else` で
   「正常」「注意」「危険」の3段階に分類しています。
   `>=`(以上)を使った条件を上から順番にチェックしていくことで、
   境界となる90や50を正しく処理しています。

2. **HTTPステータスコードの分類(switch文編)**
   `$httpStatusCode` という数値の変数を用意し、`switch` 文で
   200・301・404・500 それぞれに対応する文字列に変換しています。
   一致した `case` の処理が終わったら必ず `break;` で抜けるようにしています。

3. **HTTPステータスコードの分類(match式編)**
   同じ `$httpStatusCode` を使って、今度は `match` 式で同じ変換を行っています。
   `switch` 文よりも短く書けており、`break` も不要になっています。
   最後に、2つの結果が一致するかを `===` で確認しています。

4. **null合体演算子(??)の練習**
   `$config` という配列に、わざと `"timeout"` キーを設定しない状態を作り、
   `??` 演算子を使って「未設定ならデフォルト値30を使う」処理を実装しています。
   おまけとして、三項演算子を使った1行の条件分岐も紹介しています。

全体として、「同じ処理を複数の書き方で書いてみて、動きの違いを体感する」ことを
意識した構成になっています。

## 重要なポイント(使用した関数・構文の解説)

- **比較演算子(`>=`, `<`, `==`, `===` など)**
  数値や文字列を比較して、結果を `true`(真) か `false`(偽) で返す演算子です。
  `if` 文の条件式の中でよく使われます。

- **`if` / `elseif` / `else`**
  条件によって実行する処理を分岐させるための基本構文です。
  上から順に条件をチェックし、最初に `true` になった1つのブロックだけが実行されます。
  どの条件にも当てはまらなかった場合の処理は `else` に書きます。

- **`switch` 文**
  1つの値を複数の候補と比較して分岐したいときに使う構文です。
  `case 値:` で候補を指定し、一致した場合の処理を書いたあと `break;` で終了します。
  `break` を書き忘れると、次の `case` の処理までそのまま実行されてしまう
  「フォールスルー」という現象が起きるので注意が必要です。

- **`match` 式(PHP8以降)**
  `switch` 文と似ていますが、次のような違いがあります。
  - 値の比較が常に `===`(型まで含めた厳密比較)で行われる
  - 各分岐に `break` が不要(フォールスルーが起きない)
  - `match` 自体が「式」なので、結果をそのまま変数に代入できる
    (`$x = match(...) { ... };` のように書ける)
  条件が単純な「値の変換」であれば、`switch` よりも `match` の方が
  短く、間違いも起きにくいコードになります。

- **三項演算子(`条件 ? 真の場合 : 偽の場合`)**
  シンプルな `if`/`else` を1行で書きたいときに使います。
  例: `$label = $score >= 60 ? "合格" : "不合格";`

- **null合体演算子(`$a ?? $b`)**
  `$a` が **未定義、または `null`** のときに `$b` を返す演算子です。
  配列のキーが存在するかわからないときの「デフォルト値の設定」によく使われます。
  `isset()` を使った長い三項演算子の代わりに使えると考えるとわかりやすいです。

## 初心者がつまずきやすいポイント

- **`==` と `===` の違い**
  `==` は値だけを比較し、型が違っても値が同じとみなせれば `true` になります。
  一方 `===` は値に加えて型まで一致していないと `true` になりません。
  例えば `"200" == 200` は `true` ですが、`"200" === 200` は
  (文字列 `string` と整数 `int` で型が違うため)`false` になります。
  意図しない比較結果によるバグを防ぐため、基本的には `===` を使う習慣をつけましょう。

- **`switch` 文の `break` 忘れ**
  `switch` 文は、一致した `case` の処理が終わっても自動的には止まりません。
  `break;` を書き忘れると、後ろに書かれている別の `case` の処理まで
  そのまま実行されてしまいます。これが「フォールスルー」です。
  複数の `case` で同じ処理をまとめて実行したいとき以外は、
  必ず各 `case` の最後に `break;` を書くようにしましょう。

- **`match` 式は比較的新しい機能**
  `match` 式はPHP8.0以降でしか使えません。
  古いPHP(7系以前)の環境で動かすコードを書く場合は、
  `match` の代わりに `switch` や `if`/`elseif` を使う必要があります。

- **`elseif` の条件の範囲を勘違いする**
  「50%以上90%未満」を判定するとき、`elseif` の条件を
  `$diskFreePercent >= 50 && $diskFreePercent < 90` のように
  すべて書いてしまいがちですが、直前の `if` で「90以上」が
  すでに除外されているため、`elseif` 側では `>= 50` だけで十分です。
  上から順にチェックされるという `if`/`elseif` の性質を理解しておくと、
  条件をシンプルに書けるようになります。

## よくあるエラーと対処法

- **`Parse error: syntax error, unexpected...`**
  `if` や `switch`、`match` の括弧 `()` や波括弧 `{}` の対応が
  取れていないときに出るエラーです。開いた括弧の数と閉じた括弧の数が
  一致しているか、1つずつ数えて確認しましょう。

- **`switch` 文で意図しない結果になる**
  ある `case` に一致したはずなのに、別の `case` の結果まで
  混ざって表示される場合は、`break;` の書き忘れ(フォールスルー)を
  疑ってください。

- **`match` 式で `UnhandledMatchError` が発生する**
  `match` 式には、`switch` の `default` にあたるものとして
  `default => 値,` を書くことができます。これを省略していて、
  かつどの条件にも一致しない値が渡された場合、
  `UnhandledMatchError` という例外が発生してプログラムが止まってしまいます。
  「想定外の値が来る可能性がある」場合は、必ず `default` を用意しましょう。

- **`Warning: Undefined array key "timeout"`**
  配列に存在しないキーへ直接アクセス(例: `$config["timeout"]` を
  `??` を使わずにそのまま使う)すると、この警告が出ます。
  この演習のように `??` を使うことで、この警告を避けつつ
  デフォルト値を安全に設定できます。

## まとめ

- 比較演算子を使った条件式は、`==` と `===` の違いを意識して書くことが大切です。
- `if` / `elseif` / `else` は上から順に評価されるため、
  条件の順番と範囲の重なりに注意して設計しましょう。
- `switch` 文は `break` の書き忘れ(フォールスルー)に注意が必要ですが、
  PHP8以降で使える `match` 式ならその心配がなく、より安全でシンプルに
  「値の変換」を書くことができます。
- 三項演算子やnull合体演算子(`??`)を使うと、
  短い条件分岐やデフォルト値の設定を簡潔に書けるようになります。
- ここで学んだ「しきい値による状態判定」や「コードの分類」は、
  実際のサーバー監視ツールやログ解析ツールの中で日常的に使われている
  ロジックそのものです。今回の演習内容は、今後サーバー構築エンジニアとして
  監視の仕組みを理解したり自作したりする際の土台になります。
