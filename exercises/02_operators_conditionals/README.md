# 演習02: 演算子と条件分岐

## この演習で学ぶこと

- 算術演算子・比較演算子・論理演算子を使い分けられるようになる
- `if` / `elseif` / `else` を使って条件によって処理を分岐できるようになる
- `switch` 文と `match` 式(PHP8以降の機能)の違いを理解し、状況に応じて使い分けられるようになる
- 三項演算子とnull合体演算子(`??`)を使って、短くわかりやすい条件式が書けるようになる

## 前提知識

- 演習01(変数とデータ型)の内容を理解していること
  - 変数の宣言方法(`$変数名 = 値;`)
  - `int`(整数)、`string`(文字列)、`bool`(真偽値)などの基本的なデータ型
  - `echo` を使った画面への出力方法

## 演習内容(要件)

サーバーの状態を確認するミニツールを作るイメージで、次の2つの処理を実装します。

### 1. ディスク空き容量の判定

ディスクの空き容量(パーセント)を表す変数(例: `$diskFreePercent = 15;`)を用意し、
次のルールで状態を判定して結果を出力してください。

| 空き容量の条件 | 判定結果 |
| --- | --- |
| 90%以上 | 正常 |
| 50%以上90%未満 | 注意 |
| 50%未満 | 危険 |

この判定は `if` / `elseif` / `else` を使って実装します。

### 2. HTTPステータスコードの分類

HTTPステータスコード(例: `200`, `301`, `404`, `500` など)を表す変数を用意し、
次のように意味のある文字列に変換してください。

| ステータスコード | 変換後の文字列(例) |
| --- | --- |
| 200 | OK |
| 301 | リダイレクト |
| 404 | Not Found |
| 500 | サーバーエラー |
| 上記以外 | 不明なステータス |

この処理を **`switch` 文と `match` 式の両方** で実装し、同じステータスコードを渡したときに
両方の結果が一致することを確認できるようにしてください。

### 3. null合体演算子(`??`)の練習

「設定値が未設定(存在しない、または `null`)の場合にデフォルト値を使う」という
よくある処理を、null合体演算子 `??` を使って書いてください。
(例: タイムアウト秒数の設定が無い場合は `30` 秒をデフォルトとして使う、など)

## 実行方法

ターミナル(コマンドライン)で、この演習のディレクトリに移動してから以下のコマンドを実行してください。

```bash
# 未完成のひな形を実行してみる(エラーにはならず、TODO部分だけ「未実装」と表示されます)
php practice.php

# 模範解答を実行する
php answer.php
```

`practice.php` の中の `// TODO:` と書かれた部分を自分で実装してから、
もう一度 `php practice.php` を実行し、`answer.php` と同じような結果が出るか確認してみましょう。

## ヒント

- 比較演算子には `==`(値だけを比較する)と `===`(値に加えて型まで比較する)があります。
  `"200" == 200` は `true` になりますが、`"200" === 200` は型が違う(文字列と整数)ため `false` になります。
  意図しないバグを防ぐため、基本的には `===` を使う習慣をつけましょう。
- `switch` 文は、一致した `case` の処理が終わっても自動では止まりません。
  各 `case` の最後に `break;` を書き忘れると、そのまま次の `case` の処理まで実行されてしまいます
  (これを「フォールスルー」と呼びます)。
- `match` 式はPHP8以降で使える新しい構文です。`switch` と違って値の比較が常に `===`(厳密比較)で行われ、
  `break` を書く必要もありません。条件が単純な「値の変換」であれば `match` の方がすっきり書けます。
- 三項演算子 `条件 ? 真の場合の値 : 偽の場合の値` は、`if`/`else` を1行で書きたいときに便利です。
- null合体演算子 `$a ?? $b` は、`$a` が未定義または `null` のときに `$b` を返します。
  `isset()` を使った長い条件式を短く書けるので覚えておくと便利です。

## サーバーエンジニアとの関連

この演習で書いたロジックは、実際のサーバー監視ツールが内部で行っている処理そのものです。

- ディスクの空き容量が一定のしきい値を下回ったら警告を出す、という仕組みは、
  多くの監視ツール(Zabbix、Mackerel、Datadogなど)で標準的に使われています。
  「何%を境に注意/危険とするか」というしきい値の設計自体も、実際の運用でとても重要な考え方です。
- HTTPステータスコードを人間が読みやすい文字列に変換する処理も、
  Webサーバーのアクセスログ解析ツールや死活監視ツールの中で日常的に行われています。
  200番台は正常、300番台はリダイレクト、400番台はクライアント側のエラー、
  500番台はサーバー側のエラー、というグループ分けを覚えておくと、
  将来ログを読んだり障害対応をしたりするときに役立ちます。

## 発展課題

余裕がある人は、以下にも挑戦してみましょう。

- HTTPステータスコードの判定を、個別の数値(`200`, `301`, `404`, `500`)だけでなく、
  「100番台」「200番台」「300番台」...のように **範囲** で分類できるように改造してみましょう。
  (`match` 式では `match(true)` という書き方を使うと、`条件式 => 値` の形で範囲判定ができます。
  興味があれば調べてみてください。)
