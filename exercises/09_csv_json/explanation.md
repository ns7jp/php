# 解説: CSV・JSON操作

## コードの流れ

`answer.php` は大きく5つのパートに分かれています。

1. **パスの準備**
   `__DIR__` を使って `servers.csv`、`servers.json`、
   `servers_out.csv` の絶対パスを組み立てています。相対パスに
   頼らないことで、どのディレクトリから実行しても同じ結果になる
   ようにしています。

2. **`csvToArray()` 関数の定義(CSV→配列)**
   `fopen($path, 'r')` でCSVファイルを開き、`fgetcsv($handle)` を
   `while` ループで繰り返し呼び出して1行ずつ配列として読み込んで
   います。1行目はヘッダーとして保存し、2行目以降は
   `array_combine($header, $columns)` で連想配列に変換しています。

3. **`arrayToJsonFile()` 関数の定義(配列→JSON)**
   `json_encode($data, JSON_PRETTY_PRINT | JSON_UNESCAPED_UNICODE)`
   でPHPの配列を整形されたJSON文字列に変換し、
   `file_put_contents()` でファイルに書き出しています。

4. **`jsonFileToArray()` 関数の定義(JSON→配列)**
   `file_get_contents()` でJSONファイルの中身を文字列として読み込み、
   `json_decode($json, true)` で連想配列に変換しています。

5. **`arrayToCsvFile()` 関数の定義(配列→CSV)**
   `fopen($path, 'w')` でCSVファイルを書き込み用に開き、
   `array_keys($rows[0])` で作ったヘッダー行と、データ本体を
   `fputcsv($handle, ...)` で1行ずつ書き込んでいます。

これらの関数を順番に呼び出すことで、
「CSV → 配列 → JSON → 配列 → CSV」という一連の往復変換を実演し、
最後に最初の配列と往復後の配列を `===` で比較して、データが
壊れずに変換できていることを確認しています。

## 重要なポイント(使用した関数・構文の解説)

- **`fgetcsv($handle)`**
  開いているCSVファイルから1行を読み込み、カンマ区切りの値を
  あらかじめ配列に分解した状態で返してくれる関数です。
  `explode(",", $line)` と違い、値の中にカンマや改行、
  ダブルクォート(`"`)が含まれるCSV特有のルールまで正しく
  解釈してくれます。ファイルの終端に達すると `false` を返すため、
  `while (($columns = fgetcsv($handle)) !== false) { ... }` という形で
  「ファイルの終わりまで読み込む」ループによく使われます。

- **`fputcsv($handle, $配列)`**
  渡した配列をCSVのルールに従って1行分の文字列に変換し、
  開いているファイルに書き込む関数です。値の中にカンマや改行、
  ダブルクォートが含まれていても、必要に応じて自動的に
  ダブルクォートで囲むなどのエスケープ処理をしてくれます。

- **`array_combine($keys, $values)`**
  1つ目の配列を「キー」、2つ目の配列を「値」として組み合わせ、
  新しい連想配列を作る関数です。CSVのヘッダー行 `["name", "ip"]` と
  データ行 `["web-01", "192.168.1.11"]` を組み合わせて
  `["name" => "web-01", "ip" => "192.168.1.11"]` を作るのに
  使っています。2つの配列の要素数が一致していないとエラーになる点に
  注意してください。

- **`array_keys($array)`**
  連想配列からキーだけを取り出して、配列として返す関数です。
  `arrayToCsvFile()` の中で、1件目のデータのキー(`name`、`ip`、
  `status`)をCSVのヘッダー行として再利用するために使っています。

- **`json_encode($data, フラグ)`**
  PHPの配列(やオブジェクト)をJSON形式の文字列に変換する関数です。
  - `JSON_PRETTY_PRINT` を付けると、改行とインデントを入れて
    人間が読みやすい形に整形してくれます。
  - `JSON_UNESCAPED_UNICODE` を付けないと、日本語などの
    マルチバイト文字が `\uXXXX` 形式のコードに変換されてしまいます。
    このフラグを付けることで、日本語をそのままの文字で出力できます。
  - 複数のフラグは `|`(ビットOR演算子)でつなげて指定します。
  - 変換に失敗すると `false` を返すので、`json_last_error_msg()` と
    組み合わせてエラー内容を確認できます。

- **`json_decode($json, true)`**
  JSON文字列をPHPの値に変換する関数です。第2引数に `true` を
  渡すと連想配列として、`false`(省略時のデフォルト)を渡すと
  `stdClass` というオブジェクトとして結果を受け取ります。
  この演習では、これまで慣れ親しんだ配列の書き方(`$data['name']`
  や `foreach`)でそのまま扱えるように `true` を指定しています。

- **`fopen()` のモード `'r'` と `'w'` の違い**
  演習08では読み込み専用の `'r'` モードを使いましたが、この演習の
  `arrayToCsvFile()` では書き込み用の `'w'` モードを使っています。
  `'w'` は「ファイルが存在しない場合は新規作成し、存在する場合は
  中身を空にしてから書き込む」という意味のモードです。
  (追記したい場合に使う `'a'` モードや `FILE_APPEND` とは
  役割が異なります)

## 初心者がつまずきやすいポイント

- **`json_decode()` の第2引数を渡し忘れる**
  `json_decode($json)` のように第2引数を省略すると、結果が
  `stdClass` オブジェクトとして返ってきます。この場合
  `$data['name']` ではアクセスできず、`$data->name` のように
  アロー演算子で書く必要があり、これまでの配列の書き方と
  食い違ってエラーになります。連想配列として扱いたいときは
  必ず第2引数に `true` を渡しましょう。

- **`JSON_UNESCAPED_UNICODE` を付け忘れて、日本語が読めなくなる**
  `json_encode()` にこのフラグを付けないと、日本語の文字列が
  `"サーバー"` のような見た目に変換されて
  出力されます。データとしては壊れていませんが、人間が見ても
  内容が読めず、デバッグがしづらくなります。

- **CSVのヘッダー行を読み飛ばし忘れる**
  `fgetcsv()` はヘッダー行かデータ行かを区別してくれるわけではなく、
  単に「次の1行」を返すだけです。1行目を通常のデータとして
  `$rows` に追加してしまうと、`["name" => "web-01", ...]` の
  代わりに `["name", "ip", "status"]` のような列名そのものの行が
  混ざってしまいます。最初の1行は必ずヘッダーとして分けて
  扱いましょう。

- **`'w'` モードで既存のCSVを上書きしてしまう**
  `fopen($path, 'w')` は、指定したファイルが既に存在していても
  中身を空にしてから書き込みを始めます。追記したいつもりで
  `'w'` を使ってしまうと、それまでのデータが消えてしまうので
  注意しましょう。

- **空の配列に対して `$rows[0]` を参照してしまう**
  `arrayToCsvFile()` の中でヘッダー行を作るために `$rows[0]` を
  参照していますが、`$rows` が空配列の場合はエラーの原因になります。
  この演習の模範解答では、処理の先頭で `empty($rows)` を確認して
  早めに処理を打ち切るようにしています。

## よくあるエラーと対処法

- **`Warning: fopen(...): Failed to open stream: No such file or directory`**
  読み込もうとしたCSVやJSONファイルが指定したパスに存在しない
  場合に発生します。`servers.csv` を削除・リネームした場合や、
  `__DIR__` を使わずに相対パスを書いて別のディレクトリから
  実行した場合などに起こりやすいので、パスの組み立て方を
  確認しましょう。

- **`Warning: array_combine(): Argument #1 ($keys) and argument #2 ($values) must have the same number of elements`**
  ヘッダー行の列数と、データ行の列数が一致していないときに
  発生します。CSVの一部の行だけ列数が違う(例えばカンマの数が
  合っていない)場合に起こりやすいエラーです。CSVファイルの
  内容をよく確認してみましょう。

- **`json_decode()` の結果が `null` になる**
  JSON文字列の形式が正しくない(カンマの付け忘れや、
  クォートの閉じ忘れなど)場合、`json_decode()` は `null` を
  返します。`json_last_error_msg()` を呼び出すと、
  `"Syntax error"` のような具体的なエラー内容を確認できます。
  手でJSONファイルを編集して壊してしまった場合などに
  発生しやすいので、`json_encode()` で作った正しいJSONを
  上書きしてしまっていないか確認しましょう。

- **JSONファイルの日本語が `あ` のような表記になっている**
  エラーではありませんが、`json_encode()` に
  `JSON_UNESCAPED_UNICODE` を指定し忘れているサインです。
  第2引数のフラグを見直してみましょう。

- **書き出したCSVを開くと、想定と違う列の順番になっている**
  連想配列のキーの並び順がそのままCSVの列の並び順になります。
  `json_decode()` を経由するとキーの順番が変わってしまうことは
  基本的にありませんが、自分でデータを組み立てる際にキーの
  追加順が変わっていないか確認してみましょう。

## まとめ

この演習では、サーバー運用スクリプトで頻繁に登場する
「CSVとJSONの相互変換」を、実際に手を動かして実装しました。

- `fgetcsv()` を使うと、CSVファイルを1行ずつ安全に配列として
  読み込むことができます。
- `fputcsv()` を使うと、配列をCSVのルールに従って正しく
  ファイルに書き出すことができます。
- `json_encode()` に `JSON_PRETTY_PRINT` と
  `JSON_UNESCAPED_UNICODE` を指定すると、人間にも読みやすい、
  日本語も正しく表示されるJSONを作ることができます。
- `json_decode($json, true)` を使うと、JSON文字列を
  使い慣れた連想配列としてPHPに取り込むことができます。
- CSV→JSON→CSVのように、フォーマットを何度変換しても
  データの内容が壊れないことを確認する習慣(往復変換のテスト)は、
  実務でデータ連携処理を作るときにも役立つ考え方です。
  ここで学んだ関数の組み合わせは、監視ツールや外部APIとの
  データ連携を行うスクリプトの基本形として、そのまま応用できます。
