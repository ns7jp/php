# 解説: 簡易ログ解析ツール

## コードの流れ

`answer.php` は大きく6つのパートに分かれています。

1. **ログファイルのパスと正規表現パターンを用意する**
   `__DIR__` を使って、実行時のカレントディレクトリに関係なく
   常に同じ場所の `access_sample.log` を指せるようにしています。
   また、ログ1行から6つの情報(IPアドレス・日時・メソッド・
   パス・ステータスコード・バイト数)を取り出すための正規表現
   パターン `$pattern` をあらかじめ用意しています。

2. **`file()` でログファイルを1行ずつの配列として読み込む**
   `FILE_IGNORE_NEW_LINES`(改行を除去)と `FILE_SKIP_EMPTY_LINES`
   (空行を除外)というフラグを指定することで、あとの正規表現処理が
   しやすい、綺麗な状態の配列 `$lines` を作っています。

3. **1行だけで正規表現をテストする**
   いきなり全行を処理するのではなく、まずは `$lines[0]`
   (1行目)だけを `preg_match()` に渡してマッチするかどうかを
   確認しています。正規表現がログの形式と合っているかを
   早い段階で確かめることで、あとの全行処理でのデバッグが
   楽になります。

4. **`foreach` + `preg_match()` で全行を解析する**
   `$lines` を1行ずつ処理し、`preg_match()` でマッチした行だけを
   `"ip"` `"datetime"` `"method"` `"path"` `"status"` `"bytes"` という
   キーを持つ連想配列にまとめ、`$records` という配列に追加して
   いきます。マッチしなかった行は `$unparsedCount` で件数だけ
   数えています。

5. **ステータスコード集計・IPアドレス集計とランキング作成**
   `$records` を2回 `foreach` で回し、それぞれ
   「ステータスコードごとの件数(`$statusCounts`)」と
   「IPアドレスごとの件数(`$ipCounts`)」を、
   `$counts[$key] = ($counts[$key] ?? 0) + 1;` という
   カウンタのパターンで集計しています。
   IPアドレスの集計結果は `arsort()` で値の大きい順に並び替えたあと、
   `array_slice()` で上位5件だけを取り出し、「アクセスランキング」
   として表示しています。

6. **`preg_match_all()` によるファイル全体の一括処理(参考)**
   `file_get_contents()` でログファイル全体を1つの長い文字列として
   読み込み、`preg_match_all()` を1回呼び出すだけで、4.で
   1行ずつ処理したのと同じ件数の結果が得られることを確認しています。
   `preg_match()` を「1行ずつ」使う方法と、`preg_match_all()`を
   「複数行まとめて」使う方法の違いを体験できるようになっています。

全体を通して、「テキストデータ(ログ)を正規表現で構造化された
データ(連想配列)に変換し、それを集計して人が読める形式に
まとめ直す」という、データ処理の基本的な流れを体験する構成に
なっています。

## 重要なポイント(使用した関数・構文の解説)

- **`file(ファイルパス, フラグ)`**
  ファイルの中身を「1行が1要素になった配列」として読み込む関数です。
  `FILE_IGNORE_NEW_LINES` を指定すると各行末の改行文字が取り除かれ、
  `FILE_SKIP_EMPTY_LINES` を指定すると空行が配列に含まれなくなります。
  ログファイルのように「1行=1件のデータ」という形式のファイルを
  扱うときによく使われます。

- **正規表現パターンの読み方**
  `'/^(\S+) \S+ \S+ \[([^\]]+)\] "(\S+) (\S+) [^"]+" (\d{3}) (\d+)/m'`
  という今回のパターンは、次のような部品の組み合わせです。
  - `\S+` … 空白文字**以外**が1文字以上続く部分にマッチします
    (IPアドレスやメソッド名など、空白を含まない項目を
    ざっくり取り出すのに便利です)。
  - `[^\]]+` … `]`(閉じ角括弧)**以外**の文字が1文字以上続く部分に
    マッチします。日時は `[15/Jan/2024:10:23:45 +0900]` のように
    `[` `]` で囲まれているため、「`]` が出てくるまでの中身」を
    このパターンで取り出しています。
  - `[^"]+` … `"`(ダブルクォート)**以外**の文字が1文字以上続く
    部分にマッチします。`"GET /index.php HTTP/1.1"` の
    " HTTP/1.1" の部分のように「使わない残り」を読み飛ばすのに
    使っています。
  - `\d{3}` … 数字がちょうど3文字続く部分(ステータスコード)に
    マッチします。
  - `\d+` … 数字が1文字以上続く部分(バイト数)にマッチします。
  - `()`(丸括弧)で囲んだ部分は「グループ」と呼ばれ、
    `preg_match()` の結果(`$matches`)の中で、それぞれ
    `$matches[1]`、`$matches[2]`…という順番の要素として
    取り出せます。
  - 末尾の `m` はマルチラインモードの修飾子で、複数行を含む
    文字列に対して `^`(行頭)を「各行の先頭」として扱いたい
    ときに指定します。

- **`preg_match(パターン, 対象文字列, $matches)`**
  対象の文字列がパターンにマッチするかどうかを調べ、マッチした場合は
  `$matches` にグループごとの文字列を格納する関数です。戻り値は
  マッチした回数(0か1)なので、`if (preg_match(...) === 1)` の
  ように条件式でそのまま使えます。1つの文字列に対して
  「最初にマッチした1件」だけを調べたいときに使います
  (今回は「1行=1件のログ」なので、1行ずつ渡せば十分です)。

- **`preg_match_all(パターン, 対象文字列, $matches)`**
  `preg_match()` とよく似ていますが、対象の文字列の中に
  パターンにマッチする箇所が複数あった場合、それを**すべて**
  探し出してくれる関数です。戻り値はマッチした「件数」です。
  結果の `$matches` は、`preg_match()`のような「1件分の配列」ではなく
  「グループごとに、マッチした数だけ値が入った配列の配列」に
  なります(例: `$matches[1]` はグループ1(IPアドレス)だけを
  集めた配列)。複数行をまとめて含む1つの文字列から、
  該当する箇所を全部拾いたいときに向いています。

- **連想配列によるカウンタパターン**
  ```php
  $counts[$key] = ($counts[$key] ?? 0) + 1;
  ```
  `??`(null合体演算子)は、左側の値が存在しない(未定義)、
  または `null` のときに右側の値を使う、という演算子です。
  `$counts[$key]` がまだ1度も作られていない場合は `0` として扱い、
  そこに1を足した結果をあらためて `$counts[$key]` に代入します。
  「出てくるたびに+1する」という集計処理を、事前に
  `isset()` で存在チェックをしなくても簡潔に書けるパターンです。

- **`arsort($array)`**
  連想配列を「値の大きい順」に並び替える関数です。
  名前は "**A**ssociative **R**everse **SORT**"
  (連想配列を逆順=降順にソートする)のようなイメージで
  覚えると分かりやすいです。似た関数の `sort()` や `rsort()` は
  並び替えのときにキーを 0, 1, 2, ... に振り直してしまいますが、
  `arsort()`(および昇順の `asort()`)はキーとの対応関係を
  保ったまま並び替えてくれるため、「どのキーが何位か」を
  そのまま扱えます。

- **`array_slice($array, $offset, $length, $preserveKeys)`**
  配列の一部分だけを切り出す関数です。`$offset`(開始位置)から
  `$length` 件だけを取り出します。第4引数の `$preserveKeys` に
  `true` を指定すると、元の配列が持っていたキー(文字列キーは
  デフォルトでも保持されますが、数値キーの場合は明示的に指定
  しないと 0 番から振り直されることがあります)をそのまま
  保った状態で切り出せます。「並び替えたあとの上位n件だけ欲しい」
  という場面でよく使われます。

## 初心者がつまずきやすいポイント

- **正規表現が実際のログの形式と少しでも違うとマッチしない**
  空白の数が違う、`[` `]` を忘れている、`"` の数が合っていない
  など、ほんの少しのズレでも `preg_match()` の戻り値が `0`(マッチ
  しなかった)になり、欲しい情報が一切取れなくなります。
  README・ヒントにもある通り、いきなり全行を処理せず、
  まずは1行だけでテストして正規表現を確認する習慣をつけましょう。

- **`preg_match()` と `preg_match_all()` の結果の形が違うことに気づかない**
  `preg_match()` の `$matches` は「1件分」の配列(`$matches[1]` が
  1つの文字列)ですが、`preg_match_all()` の `$matches` は
  「グループごとに、複数件分の値が入った配列」(`$matches[1]` が
  文字列の配列)になります。同じ変数名 `$matches` を使っていても
  中身の形がまったく違う点に注意してください。

- **`preg_match_all()` を複数行の文字列に使うときに `m` 修飾子を
  忘れる**
  `^`(行頭を表す記号)は、`m` 修飾子が無い場合「文字列全体の
  一番最初」にしかマッチしません。1行ずつ `preg_match()` に
  渡している間は、その文字列自体に改行が含まれていないので
  問題になりませんが、`file_get_contents()` で読み込んだ
  「複数行を含む1つの長い文字列」に対して `preg_match_all()` を
  使う場合、`m` 修飾子を付け忘れると1行目しかマッチせず、
  「なぜか1件しか取れない」という分かりにくいバグになります。

- **カウンタ用の連想配列で `??` を使わずにいきなり `+ 1` してしまう**
  ```php
  $counts[$key] = $counts[$key] + 1; // $counts[$key] がまだ無いとエラー(Warning)になる
  ```
  のように書いてしまうと、初めて出てきたキーに対して
  「まだ存在しない配列の要素」を読み込もうとしてしまい、
  `Warning: Undefined array key` が発生します。
  `$counts[$key] = ($counts[$key] ?? 0) + 1;` のように
  `??` で「無ければ0」を明示しておくことが大切です。

- **`sort()` や `rsort()` でランキングを作ろうとしてキーが
  分からなくなる**
  `sort($ipCounts)` のような関数を使ってしまうと、値は
  並び替えられますが、キー(IPアドレス)が 0, 1, 2, ... に
  振り直されてしまい、「どのIPアドレスが何件だったか」の
  対応関係が失われてしまいます。キーとの対応を保ったまま
  並び替えたい場合は、必ず `arsort()`(降順)や `asort()`(昇順)
  を使いましょう。

## よくあるエラーと対処法

- **`preg_match()` の戻り値が `0` になり、`$matches` が空になる**
  正規表現とログの形式が一致していないことが原因です。
  `var_dump($line);` で実際の行の中身を確認し、
  空白の数やクォート・角括弧の位置が正規表現の想定と
  合っているかを1つずつ見比べましょう。

- **`Warning: preg_match(): Compilation failed`**
  正規表現の書き方自体に誤りがある(括弧が閉じられていない、
  デリミタ(`/`)の中で `/` をエスケープし忘れている、など)
  場合に発生します。パターンの `(` `)` `[` `]` の数が
  ちゃんと対応しているか数えてみましょう。

- **`Warning: Undefined array key "xxx"`**
  連想配列にまだ存在しないキーを読み込もうとしたときに出る警告です。
  カウンタ処理で `??` を使い忘れている、または `$matches[7]` の
  ように、正規表現のグループ数より大きい番号を指定してしまって
  いないかを確認しましょう(今回のパターンはグループが6個なので、
  使える添字は `$matches[1]`〜`$matches[6]` までです)。

- **`preg_match_all()` の結果件数が予想より少ない(1件しかない等)**
  対象の文字列が複数行を含んでいるのに、正規表現に `m` 修飾子を
  付け忘れているケースがほとんどです。パターンの末尾に `m` が
  付いているか確認してください。

- **`array_slice()` で上位5件を取り出したはずなのにキーが
  0, 1, 2, 3, 4 になってしまう**
  `array_slice($array, 0, 5)` のように第4引数を省略すると、
  数値キーだった場合に添字が振り直されてしまうことがあります。
  IPアドレスのような文字列キーであれば通常は保持されますが、
  癖として第4引数に `true` を指定しておくと、どんな配列に対しても
  安全にキーを保持できます。

## まとめ

- `preg_match()` は「1行(1件)から必要な情報を取り出す」処理に、
  `preg_match_all()` は「複数行(複数件)をまとめて取り出す」処理に
  向いています。複数行を含む文字列に `preg_match_all()` を使う
  場合は、`m` 修飾子で `^` の意味を「各行の先頭」に変える必要が
  ある点も覚えておきましょう。
- `$counts[$key] = ($counts[$key] ?? 0) + 1;` という
  「連想配列をカウンタとして使う」パターンは、ステータスコードの
  集計に限らず、あらゆる「出現回数を数えたい」場面で応用できる、
  非常によく使う書き方です。
- `arsort()` は値の大きい順に並び替えつつキーとの対応を保持し、
  `array_slice()` はその中から上位n件だけを取り出せます。
  この2つを組み合わせることで、「ランキングを作る」という
  集計処理を簡潔に実装できます。
- 今回作成したログ解析ツールは、実際のサーバー運用で行われる
  「アクセス傾向の把握」「異常なアクセスの発見」といった作業の
  ごく簡易な土台です。演習06・07で学んだ文字列操作・日時操作の
  知識と、今回学んだ正規表現によるパースや集計の技術を組み合わせる
  ことで、より実践的なログ分析ツールへと発展させていくことができます。
