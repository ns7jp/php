# 演習16: 簡易ログ解析ツール

## この演習で学ぶこと

- 正規表現を使って、Apache/Nginxのアクセスログ(Combined Log Format)
  からIPアドレスや日時、ステータスコードなどを取り出せるようになる
- `preg_match()` を1行ずつ呼び出す方法と、`preg_match_all()` で
  複数行をまとめて処理する方法の違いを理解する
- 連想配列を「カウンタ」として使い、ステータスコードごとの
  アクセス数を集計できるようになる
- IPアドレスごとのアクセス数を集計し、`arsort()` と `array_slice()`
  を使って「アクセスの多い上位5件」のランキングを作れるようになる
- 集計結果を、人が読んで意味の分かる形式でコンソールに表示できるようになる

## 演習内容(要件)

サーバー運用の現場でよく使われる「アクセスログの簡易解析」を、
PHPのCLIスクリプトとして作成します。

### 題材となるログファイル: `access_sample.log`

このディレクトリには、Apache/Nginxの「Combined Log Format」風の
ダミーのアクセスログファイル `access_sample.log` が20行分
同梱されています。1行の形式は次のようになっています。

```
192.168.1.10 - - [15/Jan/2024:10:23:45 +0900] "GET /index.php HTTP/1.1" 200 1234
```

それぞれの部分の意味は次の通りです。

| 部分 | 意味 | 例 |
| --- | --- | --- |
| `192.168.1.10` | アクセス元のIPアドレス | `192.168.1.10` |
| `- -` | 認証情報など(今回は使用しません) | `- -` |
| `[15/Jan/2024:10:23:45 +0900]` | アクセスした日時 | 日時文字列 |
| `"GET /index.php HTTP/1.1"` | リクエストライン(メソッド・パス・HTTPバージョン) | `GET`、`/index.php` |
| `200` | HTTPステータスコード | `200`(成功)、`404`(未検出)など |
| `1234` | レスポンスのバイト数 | `1234` |

ログの中には、`200`(成功)だけでなく `404`(未検出)、
`500`(サーバーエラー)、`301`(リダイレクト)など、
いろいろなステータスコードが混ざっています。
また、IPアドレスも複数種類混ざっており、同じIPアドレスから
何度もアクセスしている行もあります。
(すべて `192.168.x.x` のようなプライベートIPのダミーデータで、
実在のIPアドレスではありません)

### 実装する処理

`practice.php`(および模範解答の`answer.php`)では、
次の処理を順番に実装します。

1. **ログファイルの読み込み**
   `file()` 関数を使って `access_sample.log` を1行ずつの配列として
   読み込みます。

2. **正規表現によるログの解析(1行テスト → 全行処理)**
   次のような正規表現パターンを使って、1行のログ文字列から
   「IPアドレス」「日時」「メソッド」「パス」「ステータスコード」
   「バイト数」の6つの情報をグループとして取り出します。

   ```php
   $pattern = '/^(\S+) \S+ \S+ \[([^\]]+)\] "(\S+) (\S+) [^"]+" (\d{3}) (\d+)/m';
   ```

   まずは1行だけを使って `preg_match()` の結果を確認し、
   問題なくマッチすることを確かめてから、`foreach` で全行に対して
   同じ処理を行い、結果を配列(`$records`)にまとめます。

3. **ステータスコードごとの集計**
   連想配列をカウンタとして使い、`200` が何件、`404` が何件、
   といった集計を行います。

   ```php
   $statusCounts[$status] = ($statusCounts[$status] ?? 0) + 1;
   ```

4. **IPアドレスごとの集計と「アクセスランキング」の作成**
   同じカウンタのパターンでIPアドレスごとのアクセス数を集計したあと、
   `arsort()` でアクセス数の多い順に並び替え、`array_slice()` で
   上位5件だけを取り出して「アクセスランキング」として表示します。

5. **`preg_match_all()` による一括抽出(参考)**
   ログファイル全体を1つの文字列として読み込み、`preg_match_all()`
   を1回呼び出すだけで、`foreach` + `preg_match()` で1行ずつ処理した
   場合と同じ件数の結果が得られることを確認します。

## ヒント

- ログ集計では「連想配列のキーをIPアドレス(やステータスコード)に
  して、出現するたびに値を+1する」というカウンタパターンが
  よく使われます。
  ```php
  $counts[$ip] = ($counts[$ip] ?? 0) + 1;
  ```
  `??`(null合体演算子)を使うことで、「まだ1度も出てきていない
  キーかどうか」を自分でif文を書いて調べなくても、安全に
  件数を増やしていけます。
- `arsort()` は連想配列を値の大きい順に並び替えつつ、キー
  (今回はIPアドレス)との対応関係を保持してくれます。
  似た名前の `sort()` や `rsort()` はキーを 0, 1, 2, ... に
  振り直してしまうため、「どのIPアドレスが何件か」が
  分からなくなってしまいます。ランキングを作るときは
  `arsort()`(または昇順なら `asort()`)を使いましょう。
- 正規表現がログの実際のフォーマットと少しでも違うと、
  1件も数値が抽出できなくなってしまいます。いきなり全行を
  処理しようとせず、まずは1行だけを `preg_match()` に渡して
  結果を `print_r()` などで確認し、正しくマッチすることを
  確かめてから全行処理に進むと、デバッグがぐっと楽になります。
- `preg_match()` は「1行ずつ」処理するときに、`preg_match_all()`は
  「複数行をまとめて」処理するときに向いています。
  `preg_match_all()` を複数行の文字列に対して使う場合は、
  正規表現の末尾に `m`(マルチラインモード)修飾子を付けないと、
  `^` が「文字列全体の先頭」にしかマッチせず、2行目以降が
  正しく取り出せない点に注意してください。

## サーバーエンジニアとの関連

実際のインフラ運用でも「アクセスログから傾向を掴む」ことは
日常的な作業であり、この演習で作るツールはそのまま実務での
簡易分析スクリプトの土台になります。

- Webサーバー(Apache、Nginxなど)は、アクセスがあるたびに
  ログファイルへ1行ずつ記録を追記していきます。障害調査や
  負荷対策では、この大量のログを人間がすべて目で追うのは
  現実的ではないため、「集計して傾向をつかむ」ことが最初の一歩に
  なります。今回作った「ステータスコードごとの集計」は、
  「エラーが急増していないか」を確認するための最も基本的な
  チェック方法です。
- 「特定のIPアドレスから異常に多いアクセスが来ていないか」を
  調べることは、アクセス過多による負荷の調査だけでなく、
  不正アクセスやスキャン行為の兆候を発見する第一歩にもなります。
  今回作った「アクセスランキング」の仕組みは、そうした調査の
  出発点として実務でもよく使われる考え方です。
- 現場では `awk`、`grep`、`sort` といったLinuxコマンドを組み合わせて
  似たような集計を行うこともよくありますが、条件が複雑になったり、
  集計結果をさらに加工・保存(演習09で学ぶCSVやJSON出力など)
  したくなったりした場合は、PHPのような言語でスクリプトを
  書いたほうが柔軟に対応できます。今回の演習は、そうした
  「自作の簡易分析ツール」の第一歩です。
- 演習07(日付・時刻操作)で学んだ日時の扱い方と組み合わせれば、
  「特定の時間帯だけのアクセス数を集計する」「深夜帯にエラーが
  集中していないか調べる」といった、より実践的なログ分析にも
  発展させられます。

## 発展課題

余裕がある人は、以下にも挑戦してみましょう。

- ステータスコードが `500`(サーバーエラー)または `404`
  (未検出)のログだけを抽出し、「発生した日時・IPアドレス・
  パス」を一覧表示する機能を追加してみましょう。
  (ヒント: `$records` を `foreach` で回すときに、
  `if ($record["status"] === "500" || $record["status"] === "404")`
  のような条件でフィルタリングします)
  さらに余裕があれば、アクセスされた **パス(URL)ごと** の
  アクセス数ランキングも、IPアドレスのときと同じカウンタ+
  `arsort()` のパターンで作ってみましょう。
