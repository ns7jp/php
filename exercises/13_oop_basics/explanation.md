# 解説: オブジェクト指向プログラミングの基礎

## コードの流れ

`answer.php` は大きく3つのパートに分かれています。

1. **`Server` クラスを作る(クラス・プロパティ・コンストラクタ・カプセル化)**
   サーバー1台分の情報(`$name`・`$ip`・`$cpuUsage`)をまとめて扱うための
   クラスです。すべてのプロパティを `private` にして、`__construct()` で
   まとめて初期化し、値を取り出すための `getName()` などの getter と、
   CPU使用率から状態を判定する `getStatus()` を用意しています。

2. **`DatabaseServer` クラスを作る(継承・`parent::`)**
   `class DatabaseServer extends Server` として `Server` を継承し、
   データベースエンジン名を表す `$dbEngine` を追加したクラスです。
   コンストラクタの中で `parent::__construct(...)` を呼び出すことで、
   親クラス側のプロパティ初期化を `Server` に任せています。
   `getInfo()` メソッドでは、継承した `getName()`・`getIp()`・
   `getCpuUsage()` と、`parent::getStatus()` を組み合わせて、
   1行のまとめ文字列を作っています。

3. **複数のサーバーをオブジェクトの配列としてまとめ、`foreach` で一覧表示する**
   `Server` を3個、`DatabaseServer` を1個 `new` で作成し、同じ配列
   `$servers` にまとめています。`foreach` でその配列を1つずつ取り出し、
   `instanceof` 演算子で「そのオブジェクトが `DatabaseServer` かどうか」を
   判定してから、それぞれに合った表示方法で一覧を出力しています。

全体を通して、「関連するデータ(プロパティ)と、そのデータを使う処理
(メソッド)を1つのクラスにまとめる」というオブジェクト指向の基本と、
「共通する部分は親クラスにまとめ、差分だけを子クラスに書く」という
継承の考え方を体験できる構成になっています。

## 重要なポイント(使用した関数・構文の解説)

- **クラス(`class`)とオブジェクト(インスタンス)**
  `class Server { ... }` のように、関連するデータと処理をひとまとめに
  した「設計図」を定義するのが「クラス」です。`new Server(...)` のように
  `new` キーワードを使ってクラスから実際に作られた実体のことを
  「オブジェクト」または「インスタンス」と呼びます。1つのクラスから、
  値の違う複数のオブジェクトをいくつでも作ることができます。

- **プロパティ(`private string $name;` など)**
  クラスが持つ「データ」のことをプロパティ(またはメンバ変数)と
  呼びます。`private string $name;` のように、変数の前に
  アクセス修飾子(`public`/`private`/`protected`)と型を書いて宣言します。

- **アクセス修飾子(`public`/`private`/`protected`)とカプセル化**
  - `public`: どこからでもアクセスできる(クラスの外からも `->` で直接触れる)
  - `private`: そのクラス自身の中からしかアクセスできない
  - `protected`: そのクラス自身と、それを継承した子クラスからアクセスできる
    (クラスの外からは `private` と同様にアクセスできない)

  今回の演習では `$name`・`$ip`・`$cpuUsage`・`$dbEngine` をすべて
  `private` にしました。こうすることで、クラスの外から
  `$server->cpuUsage = 200;` のように直接書き換えることができなくなります。
  このように「データを外部から直接触れないように守り、決められた
  メソッド(getterなど)を経由してだけアクセスさせる」設計を
  「カプセル化」と呼びます。

- **コンストラクタ(`__construct`)**
  `__construct` という特別な名前のメソッドは、`new クラス名(...)` で
  オブジェクトを作った瞬間に、PHPが自動的に呼び出します。多くの場合、
  ここで受け取った引数をプロパティに代入し、「作られた直後から、
  すべての値がきちんとそろっているオブジェクト」を保証する役割を持ちます。

- **`$this`**
  クラスのメソッドの中で使う `$this` は、「今、このメソッドを呼び出す
  もとになった、そのオブジェクト自身」を指す特別な変数です。
  `$this->name` と書くと、「そのオブジェクトが持つ `$name` プロパティ」
  にアクセスできます。

- **getter(値を取得するためのメソッド)**
  `public function getName(): string { return $this->name; }` のように、
  `private` にしたプロパティの値を、外部から安全に読み取るための
  `public` メソッドです。プロパティを直接 `public` にせず、getter を
  1つ挟んでおくことで、「将来、値を返す前に何か処理を追加したくなった」
  ときにも、クラスの中身を直すだけで済むという柔軟性が生まれます。

- **継承(`extends`)**
  `class DatabaseServer extends Server` のように書くと、`DatabaseServer`
  は `Server` の機能(`public`/`protected` なプロパティやメソッド)を
  そのまま引き継ぎます。これにより、共通する処理(`Server` の部分)を
  1か所にまとめたまま、`DatabaseServer` には差分(`$dbEngine` や
  `getInfo()`)だけを追加で書けばよくなります。継承元のクラス
  (`Server`)を「親クラス(スーパークラス)」、継承したクラス
  (`DatabaseServer`)を「子クラス(サブクラス)」と呼びます。

- **`parent::メソッド名()`**
  子クラスの中から、親クラスの同名メソッドを明示的に呼び出すための
  書き方です。`answer.php` では、`DatabaseServer` のコンストラクタで
  `parent::__construct($name, $ip, $cpuUsage)` を呼び出し、`Server`
  クラス側のプロパティ初期化処理をそのまま再利用しています。
  また `getInfo()` の中でも `parent::getStatus()` として、親クラスの
  判定ロジックをそのまま利用しています。

- **`instanceof` 演算子**
  `$server instanceof DatabaseServer` のように書くと、「`$server` が
  `DatabaseServer` クラス(またはその子クラス)のインスタンスかどうか」を
  `true`/`false` で判定できます。`Server` と `DatabaseServer` が
  混ざった配列を扱うときに、「このオブジェクトは、追加のメソッド
  (`getInfo()` など)を持っているかどうか」を安全に確認するために使います。

- **オブジェクトの配列と `foreach`**
  PHPの配列には、数値や文字列だけでなく、オブジェクトを入れることも
  できます。`$servers = [new Server(...), new DatabaseServer(...)];`
  のように混在させた配列も、これまでと同じ `foreach ($servers as $server) { ... }`
  という書き方でそのまま1つずつ取り出すことができます。

## 初心者がつまずきやすいポイント

- **`parent::__construct(...)` の呼び忘れ**
  子クラスでコンストラクタを新しく定義すると、親クラスのコンストラクタは
  自動的には呼び出されなくなります。`parent::__construct(...)` を
  書き忘れると、親クラス側のプロパティ(`$name` など)が初期化されない
  ままになり、`getName()` などを呼び出したときにエラーになります。
  「子クラスで `__construct` を定義したら、まず `parent::__construct(...)`
  を呼ぶかどうかを考える」ことを習慣にしましょう。

- **`private` なプロパティに、クラスの外から直接アクセスしようとする**
  `$server->name` のように、`private` なプロパティにクラスの外から
  直接アクセスしようとすると、`Fatal error` になります。これは
  カプセル化が正しく機能している証拠であり、バグではありません。
  値を取得したいときは、必ず `getName()` のような getter メソッドを
  経由してください。

- **`$this->` を書き忘れる**
  クラスのメソッドの中でプロパティにアクセスするときは、
  必ず `$this->` を付けます。`$name = $name;`(`$this->` なし)のように
  書いてしまうと、プロパティではなく、そのメソッドの中だけで有効な
  「ただのローカル変数」を作ってしまい、プロパティには何も
  代入されません。

- **`->`(アロー)と `::`(ダブルコロン)の使い分け**
  `$server->getName()` のように、オブジェクト経由でメソッドや
  プロパティにアクセスするときは `->` を使います。一方、
  `parent::__construct(...)` のように、クラス名(または `parent`)を
  直接指定してアクセスするときは `::` を使います。この2つを
  混同すると構文エラーになるので注意しましょう。

- **`instanceof` を使わずに、存在しないメソッドを呼び出してしまう**
  `Server` のオブジェクトに対して、`DatabaseServer` だけが持つ
  `getInfo()` を呼び出そうとすると、`Fatal error` になります。
  `Server` と `DatabaseServer` が混在する配列を扱うときは、
  必ず `instanceof` で確認してから、それぞれに合ったメソッドを
  呼び出すようにしましょう。

## よくあるエラーと対処法

- **`Error: Typed property Server::$name must not be accessed before initialization`**
  型宣言付きのプロパティ(`private string $name;` など、初期値なし)に、
  一度も値を代入しないままアクセスしようとしたときに出るエラーです。
  多くの場合、コンストラクタの中で `$this->name = $name;` のような
  代入をし忘れているか、子クラスで `parent::__construct(...)` の
  呼び出しを忘れていることが原因です。コンストラクタの中身を
  確認しましょう。

- **`Error: Cannot access private property Server::$name`**
  `private` なプロパティに、クラスの外から `$server->name` のように
  直接アクセスしようとしたときに出るエラーです。カプセル化が正しく
  働いている証拠でもあります。`getName()` のような getter メソッドを
  経由してアクセスするように直しましょう。

- **`Error: Call to undefined method Server::getInfo()`**
  `Server` のオブジェクトに対して、`DatabaseServer` にしか定義されて
  いない `getInfo()` を呼び出そうとしたときに出るエラーです。
  `instanceof` で「そのオブジェクトが `DatabaseServer` かどうか」を
  先に確認してから呼び出すようにしましょう。

- **`Fatal error: Cannot instantiate abstract class`**
  今回の演習では登場しませんが、`abstract` を付けたクラスは
  `new` で直接オブジェクトを作ることができません
  (継承した子クラス経由でのみ利用できます)。今後、より発展的な
  内容でこのエラーに出会うことがあるかもしれません。

- **`Fatal error: Declaration of DatabaseServer::__construct() must be compatible with Server::__construct()`**
  子クラスでメソッドを上書き(オーバーライド)するとき、親クラスの
  メソッドと引数の型などに互換性がないと出るエラーです。
  コンストラクタのように引数を増やす場合は問題になりにくいですが、
  他のメソッドを上書きするときは、引数の型や個数を親クラスと
  そろえる必要がある場合がある、と覚えておきましょう。

## まとめ

- クラスは「関連するデータ(プロパティ)」と「そのデータを使った処理
  (メソッド)」を1つにまとめた設計図であり、`new` することで
  何個でもオブジェクト(インスタンス)を作ることができます。
- プロパティを `private` にし、`getName()` のような getter メソッドを
  用意することで、クラスの外から値を直接書き換えられないように守る
  「カプセル化」を実現できます。
- `extends` を使った継承により、共通する処理を親クラスにまとめたまま、
  子クラスには差分(追加のプロパティやメソッド)だけを書くことができます。
- `parent::メソッド名()` と書くと、子クラスの中から親クラスの
  同名メソッド(コンストラクタを含む)を明示的に呼び出せます。
- `instanceof` 演算子を使うと、複数の種類のオブジェクトが混在する配列を
  扱うときも、それぞれの種類に合った安全な処理を書き分けられます。
- オブジェクトが入った配列も、これまでの演習と同じ `foreach` で
  1つずつ取り出して処理できます。今回学んだ「サーバーをオブジェクトとして
  モデル化し、一覧としてまとめて扱う」考え方は、実際の監視ツールや
  インフラ自動化ツールの設計の基礎になります。
