# 解説: 日付・時刻操作

## コードの流れ

`answer.php` は大きく6つのパートに分かれています。

1. **タイムゾーンを明示的に設定する**
   `date_default_timezone_set("Asia/Tokyo")` を使って、これ以降の
   日時処理すべての「標準タイムゾーン」を日本標準時に固定しています。

2. **`date()` 関数で現在時刻を取得する**
   `date("Y-m-d H:i:s")` を呼び出すだけで、現在時刻を
   `"2026-09-01 15:06:26"` のような文字列として取得しています。

3. **`DateTime` クラスで現在時刻を取得する**
   `new DateTime()` で現在時刻を表すオブジェクトを作り、
   `->format("Y-m-d H:i:s")` で `date()` 関数と同じ書式の文字列に
   変換しています。2.の `date()` の結果と見比べて、
   「関数1回で済ませる方法」と「オブジェクトとして持つ方法」の
   違いを確認しています。

4. **`DateTimeZone` でタイムゾーンを比較する**
   `new DateTimeZone("Asia/Tokyo")` と `new DateTimeZone("UTC")` を
   作り、`new DateTime("now", タイムゾーン)` に渡すことで、
   同じ瞬間が地域によってどう見えるかを比較しています。

5. **`DateTime::diff()` でサーバーの稼働時間を計算する**
   サーバー起動時刻(固定の過去日時 `"2024-01-01 09:00:00"`)を
   表す `DateTime` と、現在時刻を表す `DateTime` を用意し、
   `diff()` メソッドで2つの日時の差分(`DateInterval` オブジェクト)を
   計算しています。その `->days`(合計日数)、`->h`(時)、`->i`(分)を
   使って、`sprintf()` で「稼働日数: n日 n時間 n分」という
   アップタイム風のメッセージを組み立てています。

6. **`strtotime()` でログのタイムスタンプを変換する**
   ログでよく見る形式の日時文字列 `"2024-06-15 08:30:00"` を
   `strtotime()` でUNIXタイムスタンプ(整数)に変換し、
   そのタイムスタンプを `date()` 関数の第2引数に渡すことで、
   `"2024年06月15日 08時30分"` という別のフォーマットに整形し
   直しています。最後に参考として、`strtotime("-1 hour", ...)` を
   使った相対的な日時計算(1時間前を求める)も紹介しています。

全体を通して、「同じ日時という情報を、関数(`date`)・オブジェクト
(`DateTime`)・整数(UNIXタイムスタンプ)という3つの異なる形で
表現し、それぞれの得意な場面を体験する」という構成になっています。

## 重要なポイント(使用した関数・構文の解説)

- **`date(書式, [タイムスタンプ])`**
  UNIXタイムスタンプ(省略時は現在時刻)を、指定した書式の文字列に
  変換する関数です。手軽に「今の日時を文字列にしたい」ときに
  よく使われます。書式に使う主な文字は次の通りです。
  - `Y` … 西暦4桁(例: `2026`)
  - `m` … 月を2桁で(例: `09`)、`M` は `Jan` のような月名の略称
  - `d` … 日を2桁で(例: `01`)
  - `H` … 24時間表記の時を2桁で、`h` は12時間表記
  - `i` … 分を2桁で(`m` は月なので間違えないように注意)
  - `s` … 秒を2桁で

- **`DateTime` クラス**
  日時を「オブジェクト」として扱うためのクラスです。
  `new DateTime()` で現在時刻、`new DateTime("文字列")` で
  文字列を解釈した日時のオブジェクトを作れます。
  作ったオブジェクトは `->format(書式)` で文字列に変換したり、
  `->diff()` のようなメソッドで他の日時と比較したりできます。
  「一度作った日時を、あとで何度も使い回したり計算したりする」
  場合には、`DateTime` クラスの方が便利です。

- **`DateTimeZone` クラス**
  「どの地域の時刻として扱うか」を表すクラスです。
  `new DateTimeZone("Asia/Tokyo")` のように地域名(タイムゾーン名)を
  指定してオブジェクトを作り、`new DateTime("now", $timezone)` の
  ように `DateTime` の第2引数に渡すことで、その地域の時刻としての
  `DateTime` オブジェクトを作成できます。

- **`DateTime::diff()` と `DateInterval`**
  `$日時1->diff($日時2)` は、`$日時1` から見て `$日時2` が
  どれだけ離れているかを計算し、`DateInterval` オブジェクトとして
  返します。`DateInterval` は次のようなプロパティを持っています。
  - `->y` `->m` `->d` … 差分の「年」「月」「日」の部分
  - `->h` `->i` `->s` … 差分の「時」「分」「秒」の部分
  - `->days` … 年月日をすべて日数に換算した「合計日数」
  `->d` と `->days` は意味が違う点に注意してください。例えば
  「1年と3日」の差であれば `->d` は `3` ですが、`->days` は
  「合計で何日離れているか」を表すもっと大きな数になります。

- **`strtotime(文字列, [基準タイムスタンプ])`**
  人間が読みやすい日時の文字列を解析し、UNIXタイムスタンプ
  (1970年1月1日 00:00:00 UTC からの経過秒数を表す整数)に
  変換する関数です。`"2024-06-15 08:30:00"` のような具体的な日時
  だけでなく、`"+1 day"`(1日後)、`"-1 hour"`(1時間前)、
  `"next monday"`(次の月曜日)のような相対的な表現も解釈できます。
  第2引数に基準となるタイムスタンプを渡すと、「そのタイムスタンプ
  から見て」という相対計算ができます(省略時は現在時刻が基準)。
  変換に失敗すると `false` を返すため、`if ($result === false)`
  のようなチェックを入れておくと安全です。

- **UNIXタイムスタンプ**
  日時を1つの整数(1970年1月1日からの経過秒数)で表したものです。
  文字列同士の日時比較は複雑になりがちですが、整数であれば
  「大小比較」や「引き算」がそのまま使えるため、日時の計算をする
  ときに便利な形式です。`date()` 関数の第2引数にタイムスタンプを
  渡すと、そのタイムスタンプが表す日時を好きな書式の文字列に
  変換できます。

## 初心者がつまずきやすいポイント

- **`date()` 関数と `DateTime` クラスをどちらも「日時を扱うもの」と
  ひとまとめに考えてしまう**
  `date()` は「その場で1回だけ文字列を作る関数」、`DateTime` は
  「日時を表すオブジェクトを作り、あとから様々な操作(`diff()` など)
  ができるクラス」という役割の違いがあります。`diff()` のような
  比較・計算をしたい場合は `DateTime` クラスを使う必要がある
  (`date()` 関数だけでは日時同士の差分は計算できない)点を
  意識しましょう。

- **書式指定の `m`(月)と `i`(分)、`M`(月名)と `m`(月)を混同する**
  `date("Y-m-d H:i:s")` の `m` は「月」、`i` は「分」です。
  「分だから `m`(minute)だろう」と勘違いしてしまうミスがよく
  あります。`i` は「時・分・秒」の並びの中で `m`(月)と重複しない
  ように選ばれた文字だと覚えておくと区別しやすくなります。

- **`DateInterval` の `->d` と `->days` を混同する**
  前述の通り、`->d` は「年月を除いた、残りの日数」、`->days` は
  「合計の日数」です。「稼働日数」のようにトータルの経過日数を
  知りたい場合に `->d` を使ってしまうと、1年以上稼働している
  サーバーで極端に小さい日数が表示されてしまいます。

- **タイムゾーンを設定し忘れて、想定と違う時刻が表示される**
  `date_default_timezone_set()` を呼ばない場合、PHPの設定
  (`php.ini` の `date.timezone`)に依存した時刻が使われます。
  開発環境と本番サーバーで設定が異なると、同じコードでも
  表示される時刻がズレて見えることがあります。日時を扱う
  プログラムの冒頭では、タイムゾーンを明示的に指定する習慣を
  つけておくと安心です。

- **`strtotime()` の戻り値をそのまま使ってしまい、失敗時に
  気づかない**
  `strtotime()` は解釈できない文字列を渡すと `false` を返しますが、
  そのまま `date("Y-m-d", false)` のように使ってしまうと、
  `false` が `0`(1970年1月1日)として扱われ、気づかないうちに
  おかしな日時が表示されてしまいます。変換後は必ず
  `=== false` で失敗していないかを確認する癖をつけましょう。

## よくあるエラーと対処法

- **`Warning: DateTime::__construct(): Failed to parse time string`**
  `new DateTime("文字列")` に渡した文字列が、日時として解釈できない
  形式だったときに発生します。タイプミスがないか、
  `"2024-01-01 09:00:00"` のような一般的な形式になっているかを
  確認しましょう。

- **`Fatal error: Uncaught Error: Call to a member function
  format() on null`**
  `$dateTime変数` が `null`(または `DateTime` オブジェクト以外)の
  状態で `->format()` を呼び出そうとすると発生します。
  `new DateTime()` の呼び出しを忘れている、条件分岐の中で
  変数が正しく代入されていない、といったことが原因になりやすいです。
  `var_dump($変数)` で中身が本当に `DateTime` オブジェクトに
  なっているか確認しましょう。

- **`strtotime()` の結果が `false` になり、その後の `date()` の
  表示がおかしくなる**
  ログのタイムスタンプ文字列の形式が想定と違う(区切り文字が
  違う、全角文字が混ざっているなど)場合に起こりやすいです。
  `var_dump($unixTimestamp);` を使って、実際に `false` が
  返ってきていないか確認しましょう。

- **`DateInterval` のプロパティ名を間違えて
  `Warning: Undefined property`**
  `->years`(複数形)のように書いてしまうと、正しくは `->y` である
  ため、意図した値が取得できません。`DateInterval` のプロパティは
  `y` `m` `d` `h` `i` `s` `days` のように、基本的に短い名前で
  統一されている点に注意しましょう。

- **タイムゾーンの違いによって、期待した時刻と9時間ズレて表示される**
  `date_default_timezone_set()` を呼び忘れたまま `date()` や
  `DateTime` を使うと、環境によっては協定世界時(UTC)を基準にした
  時刻が表示され、日本時間との9時間の差にとまどうことがあります。
  日時を扱うプログラムの冒頭で、意図したタイムゾーンを明示的に
  設定する習慣をつけましょう。

## まとめ

- `date()` 関数は「その場で手早く日時の文字列がほしいとき」に、
  `DateTime` クラスは「日時をオブジェクトとして持ち回り、
  `diff()` のような計算をしたいとき」に向いています。
  どちらも同じ書式指定(`Y` `m` `d` `H` `i` `s` など)で
  フォーマットできる点は共通しています。
- `DateTime::diff()` を使うと、2つの日時の差分を `DateInterval`
  オブジェクトとして受け取ることができ、`->days`(合計日数)や
  `->h`(時)、`->i`(分)から、アップタイムのような
  「経過時間」を表すメッセージを組み立てられます。
- `strtotime()` を使うと、文字列で書かれた日時をUNIXタイムスタンプ
  (整数)に変換できます。整数になった日時は、大小比較や引き算、
  相対的な計算(`"-1 hour"` など)がしやすくなります。
- タイムゾーンを意識しないまま日時を扱うと、環境によって時刻が
  ズレて見えるトラブルにつながります。`date_default_timezone_set()`
  や `DateTimeZone` を使って、意図したタイムゾーンを明示することが
  大切です。
- サーバーのアップタイム表示やログのタイムスタンプ処理は、
  今回学んだ「日時の取得・差分計算・フォーマット変換」の
  組み合わせそのものです。演習16のログ解析ツールでは、
  この技術を使ってログの時刻から処理時間を集計するような、
  より実践的な内容に発展していきます。
