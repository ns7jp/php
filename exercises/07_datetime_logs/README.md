# 演習07: 日付・時刻操作

## この演習で学ぶこと

- `date()` 関数と `DateTime` クラスの違いを理解し、それぞれで現在時刻を
  取得できるようになる
- `date()` / `DateTime::format()` の書式指定(`Y` `m` `d` `H` `i` `s` など)
  を使って、日時を好きなフォーマットの文字列に変換できるようになる
- `DateTime::diff()` を使って、2つの日時の差分(経過時間)を計算できる
  ようになる
- `strtotime()` を使って、文字列で書かれた日時をUNIXタイムスタンプに
  変換できるようになる
- `DateTimeZone` を使って、タイムゾーン(地域ごとの時刻)を意識した
  日時の扱い方を理解する

## 演習内容(要件)

サーバーの運用管理を意識しながら、日時に関する次の処理を実装します。

### 1. `date()` 関数で現在時刻を取得する

`date()` 関数を使って、現在時刻を `"Y-m-d H:i:s"` 形式
(例: `2026-09-01 15:06:26`)の文字列で取得してください。

### 2. `DateTime` クラスで現在時刻を取得する

`new DateTime()` で現在時刻を表すオブジェクトを作り、
`->format("Y-m-d H:i:s")` を使って `date()` 関数と同じ形式の文字列に
変換してください。`date()` 関数の結果と見比べて、
「関数で作る文字列」と「オブジェクトから作る文字列」の違いを
体感してみましょう。

### 3. `DateTimeZone` でタイムゾーンを比較する

`new DateTimeZone("Asia/Tokyo")` と `new DateTimeZone("UTC")` を作り、
`new DateTime("now", タイムゾーン)` のように渡すことで、
「日本標準時」と「協定世界時(UTC)」で同じ瞬間の時刻がどう見えるかを
表示してください(日本標準時はUTCより9時間進んでいます)。

### 4. `DateTime::diff()` でサーバーの稼働時間(アップタイム)を計算する

サーバーが起動した時刻を表す固定の日時文字列
(`"2024-01-01 09:00:00"`)から `DateTime` オブジェクトを作り、
現在時刻を表す `DateTime` オブジェクトとの差分を `diff()` メソッドで
計算してください。

`diff()` の戻り値は `DateInterval` オブジェクトで、
`->days`(合計日数)、`->h`(時)、`->i`(分)といったプロパティから
差分の内訳を取り出せます。これらを使って、

```
稼働日数: 974日 6時間 5分
```

のような、サーバーのアップタイム表示風のメッセージを組み立てて
表示してください。

### 5. `strtotime()` でログのタイムスタンプを変換する

`"2024-06-15 08:30:00"` のような、ログファイルによく登場する形式の
日時文字列を用意し、`strtotime()` を使ってUNIXタイムスタンプ
(整数)に変換してください。そのうえで、変換したタイムスタンプを
`date()` 関数の第2引数に渡し、`"Y年m月d日 H時i分"` のような、
元とは違うフォーマットの文字列に整形し直してください。

### 6. (参考)`strtotime()` の相対的な表現

`strtotime("-1 hour", $unixTimestamp)` のように書くと、
「あるタイムスタンプの1時間前」のような相対的な日時も計算できます。
この仕組みを使って、5.で変換したログ時刻の1時間前の日時を
表示する例も入っています。

## ヒント

- `DateTime` クラスはオブジェクト指向的に日時を扱え、`diff()` のような
  便利なメソッドを持っています。「日時を1つのモノとして持ち回して、
  あとからいろいろな計算をする」場合には `DateTime` クラスが向いており、
  「今すぐ1回だけ文字列がほしい」場合には `date()` 関数で手早く
  済ませられる、という使い分けを意識してみましょう。
- `date()` 関数の書式は `Y`(西暦4桁)`m`(月)`d`(日)`H`(時)`i`(分)
  `s`(秒)のように、大文字・小文字で意味が変わります。
  (例: `m` は「01」〜「12」の月ですが、`M` は「Jan」のような
  月名の略称になります)。書式を1文字間違えるだけで、まったく違う
  出力になってしまうので注意しましょう。
- タイムゾーンを意識しないと、サーバーとローカルPCで時刻がずれて
  見えることがあります。同じ「今」という瞬間でも、タイムゾーンが
  違えば表示される時刻の数字は変わります。`date_default_timezone_set()`
  で標準のタイムゾーンを設定しておく、または `DateTimeZone` で
  明示的に指定しておくと、こうした「ズレ」に振り回されにくくなります。
- `DateInterval` オブジェクトの `->days`(合計日数)と `->d`(月をまたいだ
  残りの日数)は意味が違います。「1年と3日」の差がある場合、
  `->d` は `3` ですが `->days` は「合計で何日か」を表す大きな数に
  なります。稼働日数のような「トータルで何日経過したか」を知りたい
  場合は `->days` を使うのがポイントです。
- `strtotime()` は変換に失敗すると `false` を返します。
  ログの形式が想定と違う場合に備えて、`if ($timestamp === false)`
  のようなチェックを入れておくと、実際の業務でも安全なコードになります。

## サーバーエンジニアとの関連

サーバーのアップタイム(稼働時間)計算や、ログのタイムスタンプ処理は
サーバー運用管理の基本作業です。

- Linuxサーバーには `uptime` コマンドがあり、「このサーバーが
  いつから連続稼働しているか」を確認できます。監視ツールや
  運用ダッシュボードの多くも、同じように「起動時刻と現在時刻の差」を
  計算してアップタイムを表示しています。今回作った
  「稼働日数: n日 n時間 n分」というメッセージは、まさにこの仕組みの
  簡易版です。
- Webサーバーやアプリケーションのログには、必ずと言っていいほど
  「いつ発生した出来事か」を表すタイムスタンプが記録されています。
  障害調査では「このエラーは何分前に起きたのか」「開始時刻と
  終了時刻の差(処理時間)はどれくらいか」を計算する場面が非常に
  多く、`strtotime()` や `DateTime::diff()` が活躍します。
- サーバーは日本国内だけでなく、世界中のデータセンターに置かれる
  ことも珍しくありません。タイムゾーンの扱いを誤ると、
  「ログの時刻が実際の発生時刻と9時間ズレていた」「深夜のバッチ処理が
  意図した時刻に実行されなかった」といった、原因が分かりにくい
  トラブルにつながります。`DateTimeZone` を使って明示的にタイムゾーンを
  指定する習慣は、サーバー構築・運用の現場で特に重要な考え方です。
- この演習で学んだ「日時を計算して分かりやすい形に整形する」という
  技術は、演習16のログ解析ツールで、ログの時刻から処理時間を
  集計するような、より実践的な内容につながっていきます。

## 発展課題

余裕がある人は、以下にも挑戦してみましょう。

- 複数のログのタイムスタンプ文字列(例: `"2024-06-15 08:30:00"`、
  `"2024-06-15 09:15:30"`、`"2024-06-15 10:02:10"` など3〜5個)を
  配列に用意し、`foreach` で1つずつ `strtotime()` に通してUNIX
  タイムスタンプの配列を作ってください。そのうえで、隣り合う
  ログとログの間隔(秒数)を `DateTime::diff()` や引き算で計算し、
  「1件目から2件目までの経過時間: n分n秒」のように一覧表示する
  プログラムに挑戦してみましょう(演習04で学んだ配列の扱いや、
  演習05で学んだ関数への切り出しを組み合わせるとさらに応用的です)。
