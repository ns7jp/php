# 解説: 文字列操作

## コードの流れ

`answer.php` は大きく4つのパートに分かれています。

1. **ログの1行を表す文字列を用意する**
   `"2024-01-15 10:23:45 [ERROR] Disk full on server01"` という、
   サーバーのログでよく見かける形式の文字列 `$logLine` を用意しています。

2. **`explode()` を使って分割する**
   `explode(" ", $logLine)` で半角スペース区切りに分割し、
   日付・時刻・レベル(`[ ]` 付き)・メッセージ(複数の単語に
   バラバラになったもの)を取り出しています。
   `str_replace()` で `[` `]` を取り除いてレベル名だけにし、
   `array_slice()` と `implode()` でメッセージ部分を1つの文字列に
   結合し直しています。

3. **`preg_match()` を使って一度に取り出す**
   正規表現 `'/^(\S+) (\S+) \[(\w+)\] (.+)$/'` を `preg_match()` に
   渡すことで、日付・時刻・レベル・メッセージを1回の呼び出しで
   まとめて取り出しています。

4. **2つの方法の結果を比較し、`sprintf()` で整形する**
   `explode()` で取り出した値と `preg_match()` で取り出した値が
   一致するかを `===` で比較したあと、`preg_match()` の結果を使って
   `sprintf()` で `"[ERROR] 2024-01-15 10:23:45 - Disk full on server01"`
   という見やすい形式の文字列に整形しています。最後に参考として
   `printf()` による直接出力も紹介しています。

全体を通して、「同じ目的(文字列から情報を取り出す)を、
単純な方法(`explode`)と柔軟な方法(正規表現)の両方で実現し、
それぞれの得意・不得意を体験する」という構成になっています。

## 重要なポイント(使用した関数・構文の解説)

- **`explode(区切り文字, 文字列)`**
  文字列を指定した区切り文字で分割し、配列として返す関数です。
  区切り文字が単純(今回で言えば半角スペース)な場合には便利ですが、
  「メッセージの中にも同じ区切り文字(スペース)が含まれる」ような
  ケースでは、意図した数以上に分割されてしまう点に注意が必要です。

- **`implode(区切り文字, 配列)`**
  `explode()` とは逆に、配列の要素を指定した区切り文字でつなげて
  1つの文字列にする関数です。`join()` という別名でも呼べますが、
  本教材では `implode()` を使っています。

- **`array_slice($array, $offset)`**
  配列の一部分を切り出す関数です。今回は
  `array_slice($parts, 3)` として「添字3以降の要素」だけを
  取り出し、メッセージ部分の単語だけを集めるのに使いました。

- **`trim(文字列)`**
  文字列の前後にある空白(半角スペースや改行など)を取り除く関数です。
  今回のコードでは直接使っていませんが、ファイルから読み込んだ行の
  末尾に改行コードが残っている場合など、余計な空白を取り除きたいときに
  よく使われます。ヒントや発展課題でログを配列にする際、行の末尾に
  改行が含まれていたら `trim()` で取り除くと安全です。

- **`str_replace(検索文字, 置換文字, 対象文字列)`**
  文字列の中から指定した文字(列)を探し、別の文字(列)に置き換える
  関数です。検索文字・置換文字には配列を渡すこともでき、
  `str_replace(["[", "]"], "", $text)` のように書くと、
  `"["` と `"]"` の両方を一度に取り除くことができます。

- **`preg_match(パターン, 対象文字列, $matches)`**
  正規表現のパターンを使って文字列を検索する関数です。
  マッチした場合、パターンの中で `()` を使って指定した
  「グループ」に対応する部分文字列が、第3引数に渡した変数
  (`$matches`)に配列として格納されます。
  戻り値は「マッチした回数」(0か1、エラー時は`false`)なので、
  `if (preg_match(...))` のように条件式でそのまま判定に使えます。

- **正規表現の主な記号**
  - `^` … 文字列の先頭
  - `$` … 文字列の末尾
  - `\S` … 空白以外の1文字(Space以外という意味)
  - `\w` … 英数字・アンダースコアの1文字(Wordを構成する文字)
  - `+` … 直前の文字(や記号)が1回以上連続する
  - `.` … 改行以外の任意の1文字
  - `()` … グループ化(あとで取り出せるようにまとめる)
  - `\[` `\]` … `[` `]` をそのままの文字として扱いたいときのエスケープ

- **`sprintf(書式文字列, 値1, 値2, ...)` / `printf(...)`**
  書式文字列の中の `%s`(文字列)や `%d`(整数)といった
  プレースホルダーに、続く引数を順番に当てはめた文字列を作ります。
  `sprintf()` は作った文字列を「戻り値として返す」だけなので
  変数に保存できるのに対し、`printf()` はその場で直接
  「画面に出力する」点が異なります。

## 初心者がつまずきやすいポイント

- **`explode()` だけでは複雑なログを正しく分割できないことがある**
  今回のログは「メッセージの中にもスペースが含まれる」ため、
  `explode(" ", $logLine)` をすると、メッセージが複数の要素に
  バラバラになってしまいます。「区切り文字で単純に分ける」
  `explode()` の限界を体験することが、正規表現を学ぶ動機にも
  つながります。

- **正規表現のグループ番号を数え間違える**
  `$matches[0]` は「マッチした文字列全体」であり、
  1つ目のグループは `$matches[1]` から始まる点に注意しましょう。
  `$matches[0]` を「1つ目のグループ」だと勘違いしてしまう
  ミスがよくあります。

- **`\S` と `\s`、`\W` と `\w` の大文字・小文字の違い**
  正規表現では、大文字と小文字で意味が逆になる記号があります。
  - `\s`(小文字) … 空白文字そのもの / `\S`(大文字) … 空白**以外**
  - `\w`(小文字) … 単語を構成する文字 / `\W`(大文字) … それ**以外**
  1文字の大文字・小文字を書き間違えると、まったく違う意味の
  パターンになってしまうので注意が必要です。

- **正規表現の中の `[` `]` `(` `)` `.` などは特殊な意味を持つ**
  これらの記号は正規表現の中で「文字クラス」「グループ」
  「任意の1文字」などの特別な意味を持っています。
  ログの中の `[ERROR]` のように、この記号自体を文字として
  マッチさせたい場合は `\[` `\]` のようにエスケープする必要があります。

- **`sprintf()` と `printf()` の違い、`echo` との違い**
  `sprintf()` は文字列を「返す」関数なので、`echo` を付けて
  自分で出力する必要があります。一方 `printf()` は自分で
  出力まで行うため、`echo printf(...)` のように書くと
  意図せず余計な数値(`printf()` の戻り値である出力文字数)まで
  表示されてしまうので注意しましょう。

## よくあるエラーと対処法

- **`Warning: Undefined array key` (explodeの結果に対して)**
  ログの形式が想定と異なり、`explode(" ", $logLine)` の結果の
  要素数が思ったより少ない場合に発生します。
  `print_r($parts)` などで実際の分割結果を確認する習慣をつけましょう。

- **`preg_match()` の戻り値が `0` になり、`$matches` が空になる**
  正規表現のパターンと対象の文字列が一致しなかった場合に起こります。
  ログの形式が想定と違う(例えば時刻の後ろにスペースが2つ入っている、
  レベル名に想定外の記号が含まれる、など)ことが原因になりやすいです。
  `var_dump($matches);` を使って、実際に何が入っているか
  (あるいは空であること)を確認すると原因を特定しやすくなります。

- **`Warning: preg_match(): Compilation failed`**
  正規表現の書き方自体に誤りがある場合に出るエラーです。
  `(` と `)` の数が合っていない、`/` の数が正しくない
  (開始と終了の区切り記号)などが典型的な原因です。
  複雑な正規表現を書くときは、少しずつ書いて `preg_match()` の
  戻り値を確認しながら進めると、間違いに気づきやすくなります。

- **`str_replace()` で置換したはずなのに文字が残ってしまう**
  検索文字列の指定が対象の文字列と完全に一致していない
  (例えば半角と全角の `[` `]` を取り違えている)ときに起こります。
  `var_dump()` で文字列の中身を確認し、見た目では分かりにくい
  違いがないかチェックしましょう。

- **`implode()` で結合した結果に余計なスペースが入る/入らない**
  `implode(" ", $array)` の第1引数(区切り文字)を
  `""`(空文字列)にしてしまうと単語同士がくっついてしまいます。
  逆に区切り文字を指定し忘れて `implode($array)` のように
  書いてしまうと(区切りなしで結合される)意図しない結果になるので、
  第1引数に必ず区切り文字を指定するようにしましょう。

## まとめ

- `explode()` は「単純な区切り文字での分割」に向いていますが、
  区切り文字がメッセージの中にも登場するような複雑なケースでは
  うまく分割できないことがあります。
- `preg_match()` を使った正規表現によるパターンマッチは、
  「日付」「時刻」「`[ ]` で囲まれたレベル」「残り全部がメッセージ」
  といった、より柔軟なパターンに対応できます。
- 正規表現は最初は難しく感じますが、`\S`(空白以外)、`\w`(英数字など)、
  `+`(1回以上の繰り返し)、`()`(グループ化)といった基本的な記号の
  意味を1つずつ理解していけば、少しずつ読み書きできるようになります。
- `sprintf()` / `printf()` を使うと、取り出した値を決まった書式で
  読みやすく整形して出力できます。ログの解析結果を人が読みやすい
  形にまとめるときによく使われるテクニックです。
- 今回学んだ「ログの1行から必要な情報を取り出し、整形して表示する」
  という流れは、サーバーのログ解析やエラー監視の基本そのものです。
  演習16のログ解析ツールでは、この技術を使って複数行・複数種類の
  ログをまとめて処理していきます。
