# 解説: 配列操作

## コードの流れ

`answer.php` は大きく5つのパートに分かれています。

1. **サーバー情報の多次元配列を作る**
   `"name"`(サーバー名)、`"cpu"`(CPU使用率)、`"memory"`(メモリ使用率)を持つ
   連想配列を1台分のサーバー情報として、5台分をまとめた `$servers` という
   多次元配列(添字配列の中に連想配列が入った配列)を作っています。

2. **CPU使用率が高い順に並び替える(`usort`)**
   `usort()` に「比較ルールを決める関数(コールバック関数)」を渡し、
   `$servers` をCPU使用率の高い順(降順)に並び替えています。

3. **CPU使用率が80%以上のサーバーだけを抽出する(`array_filter`)**
   `array_filter()` に「条件を判定する関数」を渡し、CPU使用率が80以上の
   サーバーだけを残した新しい配列 `$highCpuServers` を作っています。
   その後 `array_values()` でキーを振り直しています。

4. **表示用の文字列一覧を作る(`array_map`)**
   `array_map()` に「変換する関数」を渡し、各サーバーの情報を
   `"web01: CPU 85%"` のような文字列に変換した配列 `$displayLines` を作っています。

5. **平均CPU使用率を計算する(`array_reduce`)**
   `array_reduce()` を使ってCPU使用率の合計を求め、`count()` で取得した
   サーバー台数で割ることで平均値 `$averageCpu` を計算しています。

最後に「おまけ」として、`array_column()` でサーバー名だけを集めた配列を作り、
`asort()` でアルファベット順に並び替える処理も紹介しています。

全体を通して、「配列を丸ごと1つの単位として扱い、関数に処理を任せる」という
考え方(`foreach` で1件ずつ処理する代わりに、専用の関数を使う書き方)を
体験できる構成になっています。

## 重要なポイント(使用した関数・構文の解説)

- **添字配列と連想配列**
  添字配列はキーが `0, 1, 2, ...` のように自動で振られる配列です。
  連想配列はキーに自分で名前(文字列や数値)を付けられる配列です。
  `["name" => "web01", "cpu" => 85]` のように書くと、
  `"何番目の値か"` ではなく `"何の値か"` でアクセスできるようになります。

- **多次元配列**
  配列の中に配列が入っている状態を多次元配列と呼びます。
  今回の `$servers` は「添字配列(外側)の中に連想配列(内側)が並んでいる」
  多次元配列です。`$servers[0]["cpu"]` のように、外側は数値の添字、
  内側は文字列のキーでアクセスします。

- **`usort($array, $callback)`**
  配列を「値」で並び替える関数です。コールバック関数は2つの要素
  `$a`, `$b` を受け取り、並び順を表す数値(負・正・0)を返す必要があります。
  - 負の数を返す → `$a` を先にする
  - 正の数を返す → `$b` を先にする
  - 0 を返す → 順番を変えない(元の並び順が保たれるとは限りません)
  `usort()` は並び替えたあとにキーを `0, 1, 2, ...` に振り直します。

- **`array_filter($array, $callback)`**
  コールバック関数が `true` を返した要素だけを残した新しい配列を作る関数です。
  「条件に合う要素だけ残す」処理に使います。
  注意点として、要素を取り除いてもキーはそのまま引き継がれるため、
  キーが飛び飛びになることがあります。連番に振り直したいときは
  `array_values()` と組み合わせます。

- **`array_map($callback, $array)`**
  配列の全要素を1つずつ変換した、新しい配列を作る関数です。
  「全要素を変換する」処理に使います。
  `array_filter()` と違って要素の数は変わりません
  (引数の順番が `array_filter()` と逆になっている点にも注意してください)。

- **`array_reduce($array, $callback, $initial)`**
  配列の全要素を順番に処理しながら、最終的に1つの値にまとめる関数です。
  「全要素を1つの値にまとめる」処理(合計・平均・最大値など)に使います。
  コールバック関数は `$carry`(これまでの計算結果)と `$item`(今回の要素)を
  受け取り、新しい `$carry` を返します。第3引数の `$initial` は初期値で、
  配列が空だったときの安全策としても重要です。

- **`asort($array)` / `sort($array)`**
  どちらも配列を「値」で並び替える関数ですが、次の違いがあります。
  - `asort()`: 並び替えたあとも、元のキーと値の対応関係を保つ
  - `sort()`: 並び替えたあとにキーを `0, 1, 2, ...` に振り直してしまう
  どちらも「配列そのものを書き換える」関数なので、`$sorted = sort($array)`
  のように戻り値を新しい配列として受け取ることはできません
  (戻り値は成功したかどうかを表す `true`/`false` です)。

- **`array_column($array, $columnKey)`**
  多次元配列から、指定したキーの値だけを集めた新しい配列を作る関数です。
  例えば `array_column($servers, "name")` とすると、各サーバーの
  `"name"` の値だけを集めた配列(`["web01", "web02", ...]`)が得られます。

- **`count($array)`**
  配列の要素数(今回の場合はサーバーの台数)を取得する関数です。
  平均値の計算など、要素数が必要な場面でよく使います。

## 初心者がつまずきやすいポイント

- **`usort()` の比較関数の返り値の意味**
  「昇順(小さい順)にしたいから `$a - $b`、降順(大きい順)にしたいから
  `$b - $a`」と機械的に覚えてしまいがちですが、意味としては
  「`$a` を先に持ってきたいなら負の数を返す」というルールを理解しておくと、
  複雑な条件(例えば文字列の比較や複数条件の組み合わせ)にも応用できます。

- **`array_filter()` のあとにキーが飛び飛びになる**
  `array_filter()` で3台中2台が残った場合、キーは `0, 2` のように
  なることがあります。この状態で `$highCpuServers[1]` にアクセスすると
  「存在しないキー」の警告が出ます。`foreach` を使えばキーを意識せずに
  済みますが、添字でアクセスしたい場合は `array_values()` で
  キーを振り直しておくと安全です。

- **`array_map()` と `array_filter()` の引数の順番の違い**
  `array_map($callback, $array)`(コールバックが先)と
  `array_filter($array, $callback)`(配列が先)は引数の順番が逆です。
  混同しやすいので、迷ったときは公式ドキュメントで確認する習慣をつけましょう。

- **`array_reduce()` の `$carry` の意味がわかりにくい**
  最初は「前回の結果を受け取って、また返す」という流れがイメージしにくいかも
  しれません。合計を求める場合であれば、`$carry` を「これまでの合計」、
  コールバックの中で行っているのは「これまでの合計 + 今回の要素の値」を
  新しい合計として返している、とイメージすると理解しやすくなります。

- **`asort()` や `usort()` は「配列そのもの」を書き換える**
  `$sorted = usort($servers, ...)` のように書くと、`$sorted` には
  並び替え後の配列ではなく、成功したかどうかを表す `true`/`false` が
  入ってしまいます。並び替えたあとの配列は、引数として渡した変数
  (`$servers` 自身)を見る必要があります。

## よくあるエラーと対処法

- **`Warning: Undefined array key "cpu"`**
  連想配列のキー名を打ち間違えている(例: `"cpu"` のつもりが `"Cpu"` や
  `"cpu "`(余計な空白)になっている)ときによく出ます。
  配列を作った箇所とアクセスしている箇所で、キー名のスペルが完全に
  一致しているか確認しましょう。

- **`TypeError: usort(): Argument #2 ($callback) must be of type callable`**
  `usort()` の第2引数に、関数ではないもの(数値や文字列など)を
  渡してしまったときに出るエラーです。`function ($a, $b) { ... }` の形で
  無名関数を渡しているか、`return` を書き忘れていないか確認しましょう。

- **並び替えたはずなのに順番が変わらない、あるいは逆になる**
  `usort()` の比較関数の中で `$a["cpu"] - $b["cpu"]` と
  `$b["cpu"] - $a["cpu"]` を取り違えると、昇順と降順が逆になります。
  「どちらを先に持ってきたいときに、どちらの値からどちらを引くか」を
  紙に書き出して確認すると間違いに気づきやすくなります。

- **`array_reduce()` の結果が `null` になる、または警告が出る**
  第3引数(初期値)を省略した状態で空の配列を渡すと、`$carry` の
  初期値が `null` になり、意図しない計算結果になることがあります。
  合計を計算する場合は初期値に `0` を、文字列を連結する場合は
  初期値に `""`(空文字列)を指定するようにしましょう。

- **`Fatal error: Uncaught Error: Call to undefined function`**
  関数名のスペルミス(例: `array_map` を `arraymap` と書いてしまう)で
  発生します。PHPの配列関数はすべて `array_` から始まるものが多いので、
  公式マニュアル([php.net](https://www.php.net/manual/ja/ref.array.php))で
  正確な関数名を確認する習慣をつけると安心です。

## まとめ

- 添字配列は「順番」で、連想配列は「名前(キー)」で値を管理する配列です。
  多次元配列を使うと、サーバー情報のような「複数の項目を持つデータの集まり」を
  自然な形で表現できます。
- `usort()` は自分で決めたルールで配列を並び替えられる強力な関数ですが、
  比較関数が返す数値(負・正・0)の意味を正しく理解することが重要です。
- `array_filter()`(絞り込む)、`array_map()`(変換する)、
  `array_reduce()`(まとめる)は、それぞれ役割がはっきり分かれています。
  「何をしたいか」からどの関数を使うべきかを判断できるようになりましょう。
- `foreach` で1件ずつ処理するコードも、`array_map()` や `array_filter()` を
  使うことでより短く、意図が伝わりやすいコードに書き換えられることがあります。
- 今回学んだ「並び替え」「絞り込み」「集計」は、サーバー監視ダッシュボードの
  裏側で日常的に行われている処理そのものです。今後、実際の監視ツールの
  仕組みを学んだり、自分で簡単な監視スクリプトを書いたりする際の
  基礎になります。
