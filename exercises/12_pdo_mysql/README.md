# 演習12: PDOとデータベース連携

## この演習で学ぶこと

- `new PDO(DSN, ユーザー名, パスワード)` を使って、データベースに接続できる
- `PDO::setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION)` を設定し、
  エラー時に例外(Exception)を発生させて `try/catch` で扱えるようにできる
- `PDO::prepare()` と `PDOStatement::execute()` を使った
  「プリペアドステートメント」の書き方を理解し、SQLインジェクション対策
  として実装できる
- プリペアドステートメントを使って、INSERT・SELECT・UPDATE・DELETEという
  データベース操作の基本(CRUD操作)を一通り実装できる
- SQLiteとMySQLで、PDOの使い方のうち「DSN(接続文字列)だけ」が違うことを
  理解する

## 前提知識

- 演習09(CSV・JSON操作)の内容を理解していること
  - `__DIR__` を使った安全なパスの組み立て方
  - `file_exists()` によるファイルの存在確認
  - 配列(連想配列)や `foreach` を使ったデータの一覧表示
- 演習01〜06で学んだ変数、配列、関数、`if`/`foreach` などの基本
- `try` / `catch` を使った例外処理の基本的な書き方
  (「エラーが起きるかもしれない処理を `try` で囲み、エラーが起きたら
  `catch` の中で対処する」という考え方)

## 演習内容(要件)

これまでの演習では、サーバーの情報をCSVやJSONといった「ファイル」に
保存してきました。しかし、実際のWebシステムでは、大量のデータを
効率よく検索・更新・削除するために「データベース」を使うのが一般的です。

PHPからデータベースを扱うための標準的な仕組みが **PDO
(PHP Data Objects)** です。PDOを使うと、MySQL・PostgreSQL・SQLiteなど
複数の種類のデータベースを、ほとんど同じ書き方で操作できます。

本来であれば、この演習は「MySQLサーバーに接続してサーバー一覧を
管理する」という内容がぴったりですが、MySQLサーバーを別途用意する
手間をかけずに、今すぐ手元で試せるようにするため、PDOの **SQLite
ドライバ** を使います。SQLiteは、サーバーを起動する必要がなく、
1つのファイル(この演習では `servers.db`)がそのままデータベースになる、
手軽なデータベースです。

`answer.php` を実行すると、次の流れをすべて自動で行います。

1. `new PDO("sqlite:" . __DIR__ . "/servers.db")` で、
   このディレクトリに `servers.db` というデータベースファイルを
   作成し、接続する。
2. `PDO::setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION)` を
   設定し、エラー時に例外が飛ぶようにする。
3. `servers` テーブルを作成する(列: `id INTEGER PRIMARY KEY
   AUTOINCREMENT`, `name TEXT`, `ip TEXT`, `status TEXT`)。
4. プリペアドステートメント(`prepare()` と `execute([...])`)を使って、
   サーバーを2〜3件 **INSERT**(登録)する。
5. `SELECT` で全件取得し、一覧表示する。
6. `UPDATE` で1件だけ `status` を変更する。
7. `DELETE` で1件だけ削除する。
8. 変更後の一覧を再度表示して、更新・削除が反映されていることを
   確認する。

さらに、`answer.php` の中では

- SQL文字列にユーザー入力を直接連結してしまう「悪い例」を
  コメントアウトで示し、なぜそれが危険なのか(SQLインジェクション)を
  解説しています。
- ファイルの末尾に、MySQLサーバーに接続する場合はDSN(接続文字列)を
  どう変えればよいかをコメントで解説しています。

この演習で作成される `servers.db` は、動作確認用の一時的な
データベースファイルです。何度実行しても同じ結果になるように、
スクリプトの最初と最後で `servers.db` を削除するようになっています。
そのため、実行が終わったあとにこのフォルダを見ても `servers.db` は
残っていません(実行中に別のターミナルで確認したい場合は、
「よくあるエラーと対処法」の内容も参考にしてみてください)。

## 実行方法

ターミナル(コマンドライン)で、この演習のディレクトリに移動してから
以下のコマンドを実行してください。

```bash
cd exercises/12_pdo_mysql

# 未完成のひな形を実行してみる(エラーにはならず、TODO部分だけ「まだ実装されていません」と表示されます)
php practice.php

# 模範解答を実行する
php answer.php
```

`practice.php` の中の `// TODO:` と書かれた部分を自分で実装してから、
もう一度 `php practice.php` を実行し、`answer.php` と同じような結果が
出るか確認してみましょう。

構文だけを素早く確認したいときは、次のコマンドも便利です。

```bash
php -l practice.php
```

なお、Webサーバーは不要です。MySQLサーバーも用意する必要はありません。
このディレクトリで `php` コマンドを実行するだけで、PDOのSQLiteドライバが
その場でデータベースファイルを作成し、動作を確認できます。

## ヒント

- PDOはMySQL・PostgreSQL・SQLiteなど複数のデータベースを同じ書き方で
  扱えるようにする仕組みです。データベースの種類が変わっても、
  `prepare()` や `execute()`、`fetchAll()` といった書き方はほとんど
  変わりません。変わるのは、接続するときのDSN(接続文字列)くらいです。
- プリペアドステートメントを使わずにSQL文字列にユーザー入力を直接
  連結すると、SQLインジェクションという重大な脆弱性につながります。
  `answer.php` の中のコメントアウトされた「悪い例」を読んで、
  なぜ危険なのかを必ず理解しておきましょう。
- `PDO::setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION)` を
  設定しておくと、エラー時に例外(`PDOException`)が飛ぶようになり、
  `try`/`catch` で扱いやすくなります。これを設定しないと、エラーが
  起きても戻り値が `false` になるだけで気づきにくいことがあるので、
  データベースを扱うときはほぼ必須の設定だと考えてください。
- `prepare()` で用意したSQL文のひな形の中の `?` を「プレースホルダー」
  と呼びます。`execute([値1, 値2, 値3])` のように配列で値を渡すと、
  `?` の出現順に値があてはめられます。値の個数と `?` の個数を
  一致させることを忘れないようにしましょう。
- `fetchAll(PDO::FETCH_ASSOC)` を使うと、SELECTの結果を
  「連想配列の配列」として受け取れます。演習09のCSV操作で扱った
  データの形とよく似ているので、`foreach` での扱い方も同じ感覚で
  書くことができます。

## サーバーエンジニアとの関連

データベースサーバーとの連携はWebシステム運用の中核であり、
SQLインジェクション対策はセキュリティの基本中の基本です。

- 多くのWebシステムは、ユーザー情報や商品情報、そしてこの演習のような
  「サーバー一覧」といったデータをデータベースに保存して管理します。
  サーバー構築エンジニアがWebアプリケーションの構築や運用に関わる場合、
  データベースサーバー(MySQLやPostgreSQLなど)との連携は避けて
  通れない中核的な業務の1つです。
- SQLインジェクションは、Webアプリケーションの脆弱性の中でも
  特に古くから知られ、かつ今でも被害が絶えない攻撃手法です。
  データベースの中身を勝手に閲覧・改ざん・削除されてしまう
  可能性があるため、「プリペアドステートメントを使う」という
  この演習で学んだ習慣は、実務でデータベースを扱うすべての
  エンジニアにとって欠かせない基本知識です。
- 本番運用では、この演習のようにMySQLの接続情報(ホスト名や
  ユーザー名、パスワード)を管理し、正しく設定する作業自体も、
  サーバー構築エンジニアの重要な仕事の1つになります。DSNの
  組み立て方や接続エラーへの対処(`try`/`catch`)を理解しておくことは、
  そうした運用作業の土台になります。

## 発展課題

余裕がある人は、以下にも挑戦してみましょう。

- `answer.php` を改造して、`status` が `'running'` のサーバーだけを
  `SELECT ... WHERE status = ?` で絞り込んで表示する処理を
  追加してみましょう。プリペアドステートメントの `WHERE` 句にも
  `?` のプレースホルダーが使えることを確認できます。
  さらに余裕があれば、演習09で扱った `servers.csv` を読み込み、
  そこに含まれるサーバーをすべてこの演習のデータベースにINSERTする
  処理を書いてみると、「ファイルのデータをデータベースに取り込む」
  という実務でもよくある処理を体験できます。
