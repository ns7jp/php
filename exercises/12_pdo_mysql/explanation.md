# 解説: PDOとデータベース連携

## コードの流れ

`answer.php` は大きく8つのパートに分かれています。

1. **データベースファイルのパスを準備し、前回のファイルを削除する**
   `__DIR__` を使って `servers.db` の絶対パスを組み立てています。
   何度実行しても同じ結果になるように、実行の最初に
   `file_exists()` で存在確認をしてから `unlink()` で削除しています。

2. **PDOでデータベースに接続する**
   `new PDO('sqlite:' . $dbPath)` で、SQLiteドライバを使って
   `servers.db` に接続しています(ファイルが存在しない場合は
   自動的に新規作成されます)。接続に失敗する可能性があるため、
   `try`/`catch` で囲み、`PDO::setAttribute(PDO::ATTR_ERRMODE,
   PDO::ERRMODE_EXCEPTION)` を設定して、以降のエラーが例外として
   検知できるようにしています。

3. **テーブルを作成する(CREATE TABLE)**
   `$pdo->exec()` を使って、`servers` テーブルを作成しています。
   SQL文の中にユーザー入力を含まない固定の文字列なので、
   ここではプリペアドステートメントを使わず直接実行しています。

4. **プリペアドステートメントでデータを登録する(INSERT)**
   `$pdo->prepare()` でSQL文のひな形を用意し、`execute([...])` を
   3回呼び出して、サーバーを3件登録しています。あわせて、
   SQL文字列にユーザー入力を直接連結する「悪い例」をコメントアウトで
   示し、なぜ危険なのかを説明しています。

5. **全件をSELECTして一覧表示する**
   `prepare()`/`execute()`/`fetchAll(PDO::FETCH_ASSOC)` を使って
   全件を連想配列の配列として取得し、`foreach` で一覧表示しています。

6. **1件をUPDATEしてstatusを変更する**
   `UPDATE servers SET status = ? WHERE name = ?` というプレースホルダー
   付きのSQL文を使い、`execute(['stopped', 'web-02'])` で
   `web-02` の `status` を書き換えています。`rowCount()` で
   何件更新されたかを確認しています。

7. **1件をDELETEして削除する**
   `DELETE FROM servers WHERE name = ?` と `execute(['db-01'])` を
   使って、`db-01` を削除しています。

8. **後片付け**
   最後に `$pdo = null;` で接続を手放してから、`servers.db` を
   `unlink()` で削除し、何度実行しても同じ結果になるようにしています。
   ファイルの末尾には、MySQLに接続する場合の書き方をコメントで
   まとめています。

## 重要なポイント(使用した関数・構文の解説)

- **`new PDO($dsn, $username, $password)`**
  データベースに接続するためのオブジェクトを作成します。
  第1引数の `$dsn`(データソース名)は「どの種類のデータベースに、
  どうやって接続するか」を表す文字列です。SQLiteの場合は
  `"sqlite:" . ファイルパス` のように書きます。SQLiteはファイルが
  そのままデータベースになるため、ユーザー名・パスワード
  (第2・第3引数)は不要で省略できます。

- **`PDO::setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION)`**
  PDOのエラーの扱い方を設定します。この設定をしておくと、SQL文の
  間違いなどでエラーが起きたときに、戻り値が `false` になるだけ
  ではなく、`PDOException` という例外が投げられるようになります。
  例外が飛ぶことで `try`/`catch` を使ってエラーをまとめて検知できる
  ようになるため、データベースを扱うプログラムではほぼ必須の設定です。

- **`PDO::prepare($sql)` と `PDOStatement::execute($values)`**
  この演習でいちばん重要な組み合わせです。
  - `prepare($sql)` は、値の部分を `?`(プレースホルダー)にした
    SQL文の「ひな形」を用意します。この時点ではまだ実行されません。
  - `execute([値1, 値2, ...])` で、そのひな形に実際の値をあてはめて
    実行します。配列の要素は、SQL文中の `?` が現れる順番に
    対応します。
  - SQL文の「構造」と「値」がはっきり分離されているため、値の中に
    どんな文字列が入っていても、それは単なる「データ」としてしか
    扱われません。これにより、SQLインジェクションを防ぐことが
    できます。

- **`PDO::exec($sql)`**
  `CREATE TABLE` のように、結果の行を返さないSQL文を直接実行する
  ためのメソッドです。ユーザー入力を含まない固定のSQL文を実行する
  場合に使います。

- **`PDOStatement::fetchAll(PDO::FETCH_ASSOC)`**
  SELECTの実行結果を、すべて一度に「連想配列の配列」として
  取得します。1行が `["id" => 1, "name" => "web-01", ...]` の
  ような連想配列になり、`foreach` で扱いやすい形になります。

- **`PDOStatement::rowCount()`**
  直前に実行したINSERT/UPDATE/DELETEによって、何行のデータが
  変更されたかを整数で返します。「本当に更新・削除できたか」を
  確認するのに便利です。

## 初心者がつまずきやすいポイント

- **SQL文の中に変数をそのまま埋め込んでしまう**
  `"... WHERE name = '" . $name . "'"` のように文字列連結で
  SQL文を組み立てるのは、初心者がやってしまいがちな書き方ですが、
  SQLインジェクションの危険性があるため避けるべきです。値を
  使いたい部分は必ず `?` にして、`execute()` に配列として渡す
  習慣をつけましょう。

- **`?` の個数と `execute()` に渡す配列の要素数が合っていない**
  `prepare()` したSQL文の中の `?` の数と、`execute([...])` に
  渡す配列の要素数が一致していないと、エラーになります。
  `INSERT INTO servers (name, ip, status) VALUES (?, ?, ?)` であれば、
  `execute()` にも3つの値を、SQL文と同じ順番で渡す必要があります。

- **`PDO::ATTR_ERRMODE` を設定し忘れる**
  この設定をしていない状態では、SQL文が間違っていても例外が
  発生せず、単に「意図しない空の結果」が返ってくるだけで、
  エラーに気づかないままプログラムが進んでしまうことがあります。
  接続直後に必ず設定しておく習慣をつけましょう。

- **`fetchAll()` を呼ぶ前に `execute()` を忘れる**
  `prepare()` だけではSQL文はまだ実行されていません。
  `execute()` を呼び出して初めてSQL文がデータベースに対して
  実行されます。`execute()` を呼び忘れると、`fetchAll()` は
  期待した結果を返してくれません。

- **SQLiteとMySQLの違いを「書き方が全く別物」だと誤解してしまう**
  この演習で体験したように、PDOを使う限り、SQLiteとMySQLの違いは
  基本的に「接続するときのDSN(と、必要であればユーザー名・
  パスワード)」だけです。`prepare()`/`execute()`/`fetchAll()` などの
  書き方はほとんど変わらないという点をしっかり押さえておきましょう。

## よくあるエラーと対処法

- **`SQLSTATE[HY000]: General error: 1 table servers already exists`**
  すでに `servers` テーブルが存在するデータベースファイルに対して、
  もう一度 `CREATE TABLE servers` を実行しようとすると発生します。
  この演習では、スクリプトの最初に `servers.db` を削除してから
  実行し直すことで、このエラーを防いでいます。手動で `servers.db` を
  作ったまま再実行した場合などに起こりやすいエラーです。

- **`SQLSTATE[HY000] [14] unable to open database file`**
  指定したディレクトリに書き込み権限がなかったり、パスの指定を
  間違えていたりすると発生します。`__DIR__` を使って正しい絶対パスを
  組み立てているかどうかを確認しましょう。

- **`Uncaught PDOException: SQLSTATE[HY000]: ...`**
  `PDO::ATTR_ERRMODE` を `PDO::ERRMODE_EXCEPTION` に設定した状態で
  データベースの操作に失敗すると、このような例外が発生します。
  `try`/`catch` で囲んでいない部分でエラーが起きると、この演習の
  ようにスクリプトが停止してしまいます。データベース操作を行う
  重要な処理は `try`/`catch` で囲んでおくと安全です。

- **`execute()` に渡した値の個数が `?` の個数と合わずエラーになる**
  `SQLSTATE[HY093]: Invalid parameter number` のようなメッセージが
  表示されます。SQL文中の `?` の数と、`execute()` に渡す配列の
  要素数を数え直してみましょう。

- **`servers.db` を削除しようとして `unlink(): No such file or
  directory` の警告が出る**
  すでにファイルが存在しない状態で `unlink()` を呼び出すと発生します。
  この演習の模範解答のように、`unlink()` の前に必ず `file_exists()`
  で存在を確認してから削除するようにしましょう。

## まとめ

この演習では、PHPからデータベースを操作するための標準的な仕組みで
ある **PDO** を使って、接続からCRUD操作(登録・参照・更新・削除)まで
の一連の流れを実装しました。

- `new PDO($dsn, ...)` でデータベースに接続し、
  `PDO::setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION)` を
  設定しておくと、エラーを例外として安全に検知できます。
- `prepare()` と `execute([...])` を組み合わせた
  **プリペアドステートメント** を使うことで、SQLインジェクションを
  防ぎながら、安全にSQL文へ値を渡すことができます。
- `INSERT`・`SELECT`・`UPDATE`・`DELETE` という基本的なSQL操作を、
  すべて同じ「`prepare()` → `execute()`」というパターンで実装できます。
- PDOを使っておけば、SQLiteとMySQLのように接続先のデータベースの
  種類が変わっても、変更が必要なのは接続時のDSN(とユーザー名・
  パスワード)だけで、それ以降のコードはほとんど書き換えずに
  済みます。

ここで学んだ「プリペアドステートメントで安全にデータベースを
操作する」という考え方は、実際のWebシステムでデータベースを
扱う際の基本中の基本であり、そのまま実務にも応用できる知識です。
