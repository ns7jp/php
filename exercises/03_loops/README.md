# 演習03: 繰り返し処理

## この演習で学ぶこと

- `for` 文・`while` 文・`do-while` 文の違いを理解する
- `foreach` 文で配列の中身を順番に処理できるようになる
- `break` で繰り返し処理を途中で打ち切れるようになる
- `continue` でその回の処理だけをスキップし、次のループへ進められるようになる
- ネストしたループ(二重ループ)の基本的な書き方と、`break`/`continue` が
  どの範囲のループに効くのかを理解する

## 前提知識

- 演習02(演算子と条件分岐)の内容を理解していること
  - 比較演算子(`>=`, `<`, `==`, `===` など)
  - `if` / `elseif` / `else` による条件分岐
- 演習01(変数とデータ型)の内容
  - 変数の宣言方法、`echo` での出力方法
  - 配列(`$array = [...]`)の基本的な書き方(演習02までで軽く触れた範囲でOKです)

## 演習内容(要件)

サーバー運用をイメージしながら、次の内容を実装していきます。

### 0. 準備運動: for・while・do-whileの比較

まずは同じ「1から5まで数字を出力する」処理を、`for` 文・`while` 文・`do-while` 文の
3通りの書き方で比較してみましょう(このパートは `practice.php` にすでに実装済みです。
読んで理解するところから始めてください)。

とくに、条件が最初から成り立たない場合に `while` と `do-while` でどう動きが変わるかに
注目してください。

### 1. FizzBuzz(for文)

1から100までの数字について、次のルールで出力してください。

| 条件 | 出力する内容 |
| --- | --- |
| 3の倍数かつ5の倍数(=15の倍数) | `FizzBuzz` |
| 3の倍数のみ | `Fizz` |
| 5の倍数のみ | `Buzz` |
| どれにも当てはまらない | 数字そのもの |

この処理は **`for` 文** を使って実装してください。

### 2. サーバー一覧からwebサーバーだけ接続確認(foreach + continue)

サーバー名が入った配列を用意します。

```php
$servers = ["web01", "web02", "db01", "cache01"];
```

この配列を **`foreach`** で順番に処理し、名前に `"web"` という文字列を **含まない** ものは
`continue` を使って処理をスキップしてください。
`"web"` を含む名前だけ、次のように出力してください。

```
web01 に接続確認中...
web02 に接続確認中...
```

### 3. 二重ループで再現するヘルスチェックのリトライ処理

3台のサーバー(`web01`, `web02`, `db01`)に対して、それぞれ5回ずつヘルスチェックを
行ったと仮定します。実際に通信するのではなく、あらかじめ用意した
「成功(`true`)・失敗(`false`)の固定データ」を使って結果を疑似的に再現します。

```php
$healthCheckResults = [
    "web01" => [true,  true,  true,  true,  true],
    "web02" => [true,  false, false, false, true],
    "db01"  => [false, true,  false, true,  false],
];
```

外側のループでサーバーを1台ずつ取り出し、内側のループで5回分のチェック結果を
順番に確認してください。ただし、**3回連続で失敗した場合は、そのサーバーに対する
残りのチェックを `break` で打ち切り**、次のサーバーの確認に進むようにしてください
(連続失敗の回数は、途中で成功した時点でリセットします)。

上の例では、`web02` がチェック2〜4回目で3回連続失敗するため、5回目のチェックを
待たずに打ち切られるはずです。一方 `web01` は全て成功、`db01` は失敗が連続しないため、
どちらも5回すべてチェックが行われます。

## ヒント

- `for` 文は「初期化; 条件; 更新」の3つを最初に書く形です。
  `for ($i = 1; $i <= 100; $i++) { ... }` のように、
  「`$i = 1` から始めて」「`$i <= 100` の間繰り返し」「毎回 `$i++` する」という
  3つの意味を1行にまとめて書きます。
- `while` は「条件を先にチェックしてから」中身を実行するのに対し、
  `do-while` は「先に中身を1回実行してから」条件をチェックします。
  そのため `do-while` は、条件がどうであれ **最低1回は必ず実行される** という特徴があります。
- `break` はループ自体を抜け、`continue` はその回の処理だけスキップして次のループへ進みます。
  「もう繰り返し自体をやめたい」なら `break`、「今回はスキップしたいだけ」なら
  `continue` と覚えておくとよいです。
- 二重ループでは、**内側の `break` は内側のループしか抜けない** ことに注意してください。
  外側のループ(この演習では「サーバーごとの繰り返し」)はそのまま続行されます。
- 文字列に特定の文字列が含まれているかどうかは、`str_contains($文字列, $探したい文字列)`
  という関数(PHP8以降)で調べられます。`true`/`false` が返ってくるので、
  `if` の条件式にそのまま使えます。
- 数値が「3の倍数かどうか」は、剰余演算子 `%` を使って `$number % 3 === 0` で判定できます。

## サーバーエンジニアとの関連

複数サーバーへの一括処理(バッチ処理)やヘルスチェックの再試行(リトライ)ロジックは、
繰り返し処理の典型的な実務利用例です。

- 「サーバー一覧を1台ずつ処理する」という `foreach` の使い方は、
  複数台のサーバーに同じ設定を配布したり、まとめてコマンドを実行したりする
  バッチ処理・構成管理ツール(Ansibleなど)の考え方そのものです。
  今回のように「名前に特定の文字列を含むサーバーだけ対象にする」という絞り込みも、
  「webサーバー群だけ再起動する」「dbサーバー群だけバックアップする」といった
  実務の場面でよく登場します。
- 「ヘルスチェックに失敗したら、一定回数までリトライしてダメなら諦める」という考え方は、
  ロードバランサーや監視ツールが実際にサーバーの死活監視を行うときの基本的な仕組みです。
  1回の失敗だけですぐに「サーバーダウン」と判断してしまうと、
  一瞬の通信の乱れなどで誤検知してしまう可能性があるため、
  「何回連続で失敗したら異常とみなすか」というしきい値の設計が重要になります。
  今回の演習で書いた「3回連続失敗したら打ち切る」という処理は、
  まさにこの考え方を単純化して再現したものです。

## 発展課題

余裕がある人は、以下にも挑戦してみましょう。

- 3台のうち **どれか1台でも5回全て失敗した(全滅した)** 場合は、
  そのサーバーだけでなく、残りのサーバーのチェックも含めて
  ヘルスチェック処理全体を中止する、という仕様に変更してみましょう。
  PHPの `break` には `break 2;` のように数字を指定する書き方があり、
  これを使うと内側だけでなく外側のループも同時に抜けることができます。
  興味があれば調べて使ってみてください。
