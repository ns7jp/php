# 解説: フォーム処理とバリデーション

## コードの流れ

`answer.php` は大きく6つのパートに分かれています。

1. **`$_GET` / `$_POST` をCLI用にシミュレートする**
   本来はWebブラウザからのリクエストに応じてPHPが自動的に用意する
   `$_GET`・`$_POST` に、コマンドラインでも試せるよう直接配列を
   代入しています。`$_GET["id"]` は「どのサーバーを対象にするか」を
   表すIDの例、`$_POST` は「登録する」ボタンを押したときに送信される
   ホスト名・IPアドレス・ポート番号の例です。

2. **`$_GET` の値を表示する**
   `$_GET["id"]` を `htmlspecialchars()` に通してから画面に表示し、
   「外部から渡された値は表示前にエスケープする」という基本の型を
   確認しています。

3. **必須チェック(ホスト名)**
   `empty($hostname)` を使って、ホスト名が入力されているかを
   チェックしています。問題があれば `$errors` 配列にメッセージを
   追加します。

4. **書式チェック(IPアドレス・ポート番号)**
   `filter_var()` を使い、IPアドレスは `FILTER_VALIDATE_IP` で、
   ポート番号は `FILTER_VALIDATE_INT` と `min_range`/`max_range` の
   オプションで、それぞれ形式が正しいかをチェックしています。
   どちらも失敗すると `false` が返ってくるので、`===` で判定して
   `$errors` にメッセージを追加します。

5. **チェック結果の表示**
   `$errors` が空であれば「登録可能です」、そうでなければ
   `foreach` でエラー内容を一覧表示しています。ここでも画面に表示する
   ホスト名は `htmlspecialchars()` を通しています。

6. **XSS対策のデモ**
   `<script>alert('XSS')</script>` という「悪意のある入力」を例にして、
   `htmlspecialchars()` を通す前と後で見た目がどう変わるかを比較し、
   なぜこの処理が必要なのかを確認しています。

全体を通して、「1つの入力ごとに、必須チェック → 書式チェック →
エラーをためる → まとめて結果を表示する」という、
Webアプリケーションのフォーム処理でとてもよく使われる流れを
体験できる構成になっています。

## 重要なポイント(使用した関数・構文の解説)

- **`$_GET` と `$_POST`**
  どちらもPHPが自動的に用意してくれる「スーパーグローバル変数」で、
  どこからでも(関数の中からでも)アクセスできる連想配列です。
  - `$_GET`: URLのクエリ文字列(`?key=value&...`)から作られる値。
    「このページで何を表示するか」「どのデータを対象にするか」を
    指定するのによく使われます。
  - `$_POST`: `<form method="post">` から送信されたフォームの
    入力内容。サーバー側のデータを変更する処理(登録・更新・削除)を
    行うときによく使われます。
  - どちらも「配列のキーに文字列を指定してアクセスする」という
    使い方は同じです(例: `$_POST["hostname"]`)。

- **`empty($value)`**
  変数が「未定義」「空文字列 `""`」「`null`」「数値の `0`」
  「空配列 `[]`」などのいずれかに当てはまる場合に `true` を返す関数です。
  「そもそも値が入力されているか」という必須チェックによく使われます。

- **`filter_var($value, $filter, $options)`**
  値をあるルール(フィルター)に沿ってチェック・変換する関数です。
  - `filter_var($ip, FILTER_VALIDATE_IP)`
    IPv4・IPv6として正しい形式かどうかをチェックします。
    正しければそのままの値、正しくなければ `false` を返します。
  - `filter_var($port, FILTER_VALIDATE_INT, ["options" => ["min_range" => 1, "max_range" => 65535]])`
    文字列で渡された値が整数として解釈でき、かつ指定した範囲
    (ここでは1〜65535)に収まっているかをチェックします。
    成功すると int 型の値が、失敗すると `false` が返ります。
  - このほかにも `FILTER_VALIDATE_EMAIL`(メールアドレス)や
    `FILTER_VALIDATE_URL`(URL)など、実務でよく使う形式のフィルターが
    あらかじめ用意されています。

- **`htmlspecialchars($string)`**
  文字列の中の `<`・`>`・`"`・`'`・`&` を、それぞれ対応するHTML
  エンティティ(`&lt;`・`&gt;`・`&quot;`・`&#039;`・`&amp;`)に
  変換する関数です。ユーザーが入力した文字列や、URLから受け取った
  値など「外部から渡された値」を画面(HTML)に表示する前には、
  必ずこの関数を通すのが基本です。

- **`=== false` による厳密な比較**
  `filter_var()` は失敗すると `false` を返しますが、成功時の値が
  `0` や `""` になるケースもあり得るため、`==` (緩い比較)で
  判定すると意図しない結果になることがあります。
  `=== false` のように型まで含めて比較する「厳密な比較演算子」を
  使うことで、正確に失敗を判定できます。

- **配列にエラーメッセージをためていく (`$errors[] = "..."`)**
  `$errors[] = "..."` は、配列 `$errors` の末尾に新しい要素を
  追加する書き方です。チェックのたびに問題があればこの形で
  追加していき、最後に `foreach` でまとめて表示することで、
  「全部の項目を一度にチェックしてから結果を伝える」フォームに
  なっています。

## 初心者がつまずきやすいポイント

- **`$_GET` と `$_POST` の役割を混同してしまう**
  どちらも「外部から渡ってきた値」という点は同じですが、
  `$_GET` は主に「どのデータを見る/対象にするか」を表すのに向いていて
  (URLとして共有・ブックマークしやすい)、`$_POST` は主に
  「実際に送信するデータの中身」を表すのに向いています
  (フォームの入力内容のような、URLに出したくない・出せない量の
  データを送るのに向いている)。今回の演習のように、
  「編集対象のID = GET」「実際に登録する内容 = POST」と
  役割分担して考えると理解しやすくなります。

- **`filter_var()` の失敗を `if (!$result)` で判定してしまう**
  `filter_var($port, FILTER_VALIDATE_INT, ...)` が `0` を返すことは
  あり得ませんが(範囲が1〜65535のため)、他のケースでは
  「有効な値としての `0`」と「チェック失敗の `false`」を
  `if (!$result)` のような緩い書き方で判定すると区別できなくなる
  ことがあります。必ず `=== false` で比較する習慣をつけましょう。

- **`empty()` の対象にできる範囲を誤解する**
  PHPのバージョンによっては、`empty()` に関数の戻り値を直接渡せない
  (変数にしか使えない)場合があります(古いPHPバージョンの制限です)。
  最近のPHPでは `empty(trim($value))` のような書き方もできますが、
  迷ったら一度変数に代入してから `empty()` を使うと安全です。

- **`htmlspecialchars()` を「入力を受け取った直後」に使ってしまう**
  `htmlspecialchars()` は「画面(HTML)に表示する直前」に使うのが
  基本です。データを受け取った時点ですぐにエスケープしてしまうと、
  データベースに保存する値やバリデーション処理の対象の値まで
  変換されてしまい、意図しない不具合につながることがあります。
  「バリデーションや保存は元の値のまま行い、表示するときだけ
  `htmlspecialchars()` を通す」という順番を意識しましょう。

- **1つエラーが見つかった時点で処理を止めてしまう**
  `if (empty($hostname)) { echo "エラー"; return; }` のように
  最初のエラーだけを見て処理を終わらせてしまうと、
  ユーザーは1回の送信で1つのエラーしか知ることができません。
  今回のように `$errors` 配列にすべての問題をため込んでから
  まとめて表示するほうが、ユーザーにとって親切なフォームになります。

## よくあるエラーと対処法

- **`Warning: Undefined array key "hostname"`**
  `$_POST["hostname"]` のキーが存在しない場合に発生します。
  実際のフォームでは、入力欄自体が送信されなかったり、
  HTMLの `name` 属性のスペルミスなどで発生することがあります。
  `$_POST["hostname"] ?? ""` のように `??`(null合体演算子)を
  使って「存在しない場合の初期値」を指定しておくと安全です。

- **IPアドレスのチェックが常に失敗してしまう**
  `filter_var()` に渡す値の前後に、気づかないうちに空白や改行が
  含まれている場合があります(フォームの入力欄に余計なスペースが
  入ってしまうことはよくあります)。`trim($ip)` で前後の空白を
  取り除いてから `filter_var()` に渡すようにすると安定します。

- **ポート番号のチェックで、数値のはずなのに失敗する**
  `FILTER_VALIDATE_INT` は「数字だけで構成された文字列」を期待して
  います。全角数字(`"８０８０"` など)や、数字の前後に余計な文字列
  (`"8080番"` など)が混ざっていると失敗します。
  `var_dump($port)` で実際にどんな値が入っているか確認する習慣を
  つけましょう。

- **`htmlspecialchars()` を通した結果、文字化けしたように見える**
  `htmlspecialchars()` は初期状態でも多くの環境で正しく動作しますが、
  文字コードの扱いで迷ったときは
  `htmlspecialchars($value, ENT_QUOTES, "UTF-8")` のように
  文字コードを明示的に指定すると安定します
  (`ENT_QUOTES` はシングルクォート `'` もエンティティに変換する
  オプションです)。

- **`Fatal error: Uncaught TypeError` (filter_varの引数の型)**
  `filter_var()` の第1引数に配列や `null` を渡すと、
  PHPのバージョンによってはエラーになることがあります。
  `$_POST` から取り出した値がそもそも文字列になっているかを
  事前に確認する(あるいは `(string)` でキャストする)と
  防ぐことができます。

## まとめ

- `$_GET` は「どのデータを対象にするか」、`$_POST` は「実際に送信された
  データの中身」というように、役割が異なるスーパーグローバル変数です。
- `filter_var()` を使うと、IPアドレスや整数の範囲チェックのような
  「よくある形式の検証」を、自分で正規表現を書かなくても短いコードで
  行うことができます。判定の際は `=== false` で厳密に比較しましょう。
- 必須チェックには `empty()` が便利ですが、対象になる値の種類
  (`0` や `"0"` も `true` 扱いになる点など)には注意が必要です。
- ユーザーからの入力やURLパラメータなど「外部から渡された値」を
  画面(HTML)に表示するときは、必ず `htmlspecialchars()` を通して
  XSS(クロスサイトスクリプティング)を防ぎましょう。
  これはサーバー構築・運用に関わるエンジニアにとって基礎中の基礎となる
  セキュリティ対策です。
- エラーは1件見つかるごとに処理を止めるのではなく、配列にため込んで
  最後にまとめて表示することで、使う人にとって親切なフォームになります。
