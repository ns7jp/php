# 演習10: フォーム処理とバリデーション

## この演習で学ぶこと

- `$_GET` と `$_POST` それぞれの役割の違いを理解する
- `filter_var()` を使って、IPアドレスや整数など「よくある形式」の値を
  1行でチェックできるようになる
- `htmlspecialchars()` を使ったXSS(クロスサイトスクリプティング)対策の
  必要性を理解する
- 「必須チェック」と「書式チェック」を組み合わせて、
  エラーを配列にためて一覧表示するロジックを組み立てられるようになる

## 前提知識

- 演習06(文字列操作)の内容を理解していること
  - 文字列の中身を確認したり、整形して表示したりする感覚
- 演習01〜04で学んだ変数、データ型、条件分岐、配列の基本
  - 特に配列に要素を追加していく操作(`$errors[] = "..."` のような書き方)
- 演習05(関数の作成)で学んだ、処理をひとまとまりにする考え方
  (この演習では必須ではありませんが、知っているとコードが読みやすくなります)

## 演習内容(要件)

サーバー管理ツールの「サーバー登録フォーム」を想定します。
本来はHTMLの `<form>` から送信されてブラウザ側で入力される値ですが、
この演習では **CLI(コマンドライン)だけで動作確認できるように**、
`$_POST` にあらかじめ次のような配列を直接代入してシミュレートします。

```php
// 本来はHTMLフォームがブラウザから送信してくる値ですが、
// この演習ではCLIで試せるように直接配列を代入しています。
$_POST = [
    "hostname" => "web01",
    "ip"       => "192.168.1.10",
    "port"     => "8080",
];
```

あわせて、`$_GET` についても簡単なシミュレーションを行います。
サーバー一覧画面で「編集」リンク(例: `edit.php?id=5`)をクリックしたときのように、
「どのサーバーを対象にした操作か」を表すID値を `$_GET["id"]` に用意します。

```php
$_GET = [
    "id" => "5",
];
```

このプログラムでは、次の3つの項目をバリデーション(検証)してください。

1. **ホスト名(`hostname`)**
   - 空文字列でないこと(`empty()` を使って必須チェックを行う)
2. **IPアドレス(`ip`)**
   - `filter_var($value, FILTER_VALIDATE_IP)` を使って、
     正しい形式のIPアドレスであることを確認する
3. **ポート番号(`port`)**
   - `filter_var($value, FILTER_VALIDATE_INT, ["options" => ["min_range" => 1, "max_range" => 65535]])`
     を使って、1〜65535の範囲の整数であることを確認する

チェックの結果、問題があった項目は理由をエラーメッセージとして
`$errors` という配列にため込んでいってください。
最終的に、

- `$errors` が空であれば「登録可能です」というメッセージを表示する
- `$errors` に1件でもメッセージが入っていれば、
  エラー内容を一覧で分かりやすく表示する

という分岐を行ってください。

また、ユーザーが入力した文字列(ホスト名や `$_GET["id"]` など)を
画面に表示する箇所では、**必ず `htmlspecialchars()` を通してから**
出力するようにしてください。これは今回はCLIでの実行なので実害は
ありませんが、「Webページに表示する前提のデータは常にエスケープする」
という習慣そのものが今回の学習ポイントです(詳しくは
「サーバーエンジニアとの関連」と `explanation.md` で説明します)。

## 実行方法

ターミナル(コマンドライン)で、この演習のディレクトリに移動してから
以下のコマンドを実行してください。

```bash
# 未完成のひな形を実行してみる(エラーにはならず、TODO部分だけ「まだ実装されていません」と表示されます)
php practice.php

# 模範解答を実行する
php answer.php
```

`practice.php` の中の `// TODO:` と書かれた部分を自分で実装してから、
もう一度 `php practice.php` を実行し、`answer.php` と同じような結果が出るか
確認してみましょう。

構文だけを素早く確認したいときは、次のコマンドも便利です。

```bash
php -l practice.php
```

試しに `$_POST["ip"]` の値を `"999.999.999.999"` のような不正な値に
書き換えたり、`$_POST["port"]` を `"70000"` や `"abc"` に書き換えたりして、
エラーメッセージがどのように変化するかを確認してみるとより理解が深まります。

## ヒント

- `$_POST` や `$_GET` は本来ブラウザのフォームから送られてくる値ですが、
  この演習ではCLIで試せるよう配列を直接用意しています。
  実際のWebアプリケーションでは、`<form method="post">` で送信された値が
  `$_POST` に、URLの `?key=value` の部分(クエリ文字列)が `$_GET` に
  自動的に格納されます。
- `filter_var()` はメールアドレスやIPアドレスなど、よくある形式のチェックを
  1行で行える便利な関数です。自分で正規表現を書かなくても、
  `FILTER_VALIDATE_IP` や `FILTER_VALIDATE_INT` のような「フィルターの種類」を
  指定するだけでチェックできます。
- `htmlspecialchars()` は `<` や `>` などのHTMLタグとして解釈される文字を
  無害な文字列(`&lt;` や `&gt;` など)に変換し、
  XSS(クロスサイトスクリプティング)を防ぎます。
  「ユーザーが入力した値を画面に表示するときは、必ずこれを通す」と
  覚えておきましょう。
- `empty($value)` は、変数が「未設定」「空文字列 `""`」「`null`」
  「数値の `0`」などの場合に `true` を返します。今回のホスト名チェックのように
  「文字列が入力されているかどうか」を確認する用途でよく使われます。
- `filter_var()` は、チェックに失敗すると **`false`** を返します。
  `0`(数値のゼロ)や空文字列と紛らわしいので、
  `if ($result === false)` のように **厳密な比較(`===`)** で
  失敗判定をするのが安全です。
- エラーメッセージは配列にどんどん追加していき(`$errors[] = "..."`)、
  最後にまとめて `foreach` で一覧表示すると、
  「1つエラーが見つかったら処理を止める」のではなく
  「全部の項目をチェックしてから、まとめて結果を教える」という
  ユーザーにやさしいフォームが作れます。

## サーバーエンジニアとの関連

サーバー管理画面でホスト名やIPアドレスを登録・編集する機能を作る際、
この種の入力チェックは実務で必ず必要になります。

- サーバー管理ツールや監視ツールの管理画面では、
  「新しいサーバーを登録する」「既存のサーバー情報を編集する」といった
  フォームが数多く存在します。ホスト名の入力欄が空のまま登録されたり、
  IPアドレスの欄に `"192.168.1.999"` のような存在しない値が入ったり、
  ポート番号の欄に文字列や範囲外の数値が入ったりすると、
  そのデータを使って通信しようとしたときにエラーが発生したり、
  最悪の場合は誤って別のサーバーに接続してしまうといった事故につながります。
- サーバー側(PHP側)でのバリデーションは、ブラウザ側のJavaScriptによる
  チェックだけに頼れない場面で特に重要です。JavaScriptは無効化されたり、
  ブラウザを使わずに直接HTTPリクエストを送られたりすることもあるため、
  「最終的にデータを受け取るサーバー側で必ずもう一度チェックする」のが
  安全なシステムの基本です。
- また、管理画面にはユーザーが入力した値(ホスト名やメモ欄など)を
  そのまま一覧表示する機能がよくあります。このとき `htmlspecialchars()` を
  忘れると、悪意のある人がホスト名の欄に `<script>` タグを含む文字列を
  登録し、それを見た別の管理者のブラウザで不正なスクリプトが実行されて
  しまう「XSS(クロスサイトスクリプティング)」という脆弱性につながります。
  サーバー構築・運用を仕事にするなら、この対策は必須の基礎知識です。

## 発展課題

余裕がある人は、以下にも挑戦してみましょう。

- ホスト名にも「英数字とハイフンのみ、63文字以内」のような
  形式チェックを追加してみましょう。`preg_match('/^[a-zA-Z0-9-]{1,63}$/', $hostname)`
  (演習06で学んだ正規表現)を使うと実現できます。
  さらに「先頭・末尾がハイフンではないこと」まで確認できると、
  より実務に近いバリデーションになります。
